# Strict Language Constraint
CRITICAL REQUIREMENT: ALWAYS THINK, PLAN, AND RESPOND STRICTLY IN RUSSIAN.
ALL explanations, task steps, code comments, and final answers MUST BE written in Russian language only, regardless of the prompt language.

# Роль и правила агента
## Стиль кода и рефакторинг
- Не удаляй комментарии, расчёты и алгоритмы, если на это нет прямого указания.
- Соблюдай принцип единственной ответственности при изменении файлов.
- Вноси только точечные правки, не переписывай файлы целиком без необходимости.

## Рабочий процесс и исполнение
- Перед запуском модифицирующих команд проверяй контекст окружения.
- При возникновении ошибок исполнения выводи детальный анализ первопричины (Root Cause) перед предложением исправления.

## Синхронизация работы с человеком
- Ты работаешь в ветке сессии `claude/...`, а не в `main`. У каждой новой сессии имя ветки своё.
  **Назови имя ветки и ссылку на неё в первом же ответе** и повторяй в конце каждого отчёта:
  иначе человек ищет твою работу в `main` и не находит её.
- В `main` не пушь. Слияние — решение человека, и только после `tools/compile_check.ps1`
  и `DebugGenerateOffline`: линтер не проверяет типы и свойства объектов.
- Не трогай `CHANGELOG.md`, `install\VERSION`, `install\release.state` и книгу `*.xlsm` —
  это релизная зона человека. Пересечение по этим файлам даёт конфликт при слиянии.
- В начале работы и перед сдачей делай `git merge origin/main` в свою ветку, чтобы она
  не отставала и диф оставался читаемым.
- Подробнее — `docs/rules.md`, раздел «Синхронизация с ИИ-агентом».

## СИГНАТУРЫ
Для модулей, у которых есть файл сигнатуры (`./src/sig/<ИмяМодуля>.sig.md`):

1. Если статус в сигнатуре `CLEAN` — для решений "нужно ли трогать этот модуль" и для общих вопросов о нём ("что делает функция X", "какие есть процедуры") читать **только сигнатуру**, не открывать исходный код.

2. Если статус `DIRTY` — сигнатуре не доверять. Любой вопрос об этом модуле требует чтения полного кода, даже если вопрос не связан с правкой.

3. Если модуль нужно **редактировать** — читать полный исходный код всегда, независимо от статуса сигнатуры. Сигнатура никогда не заменяет код при правке.

4. Сразу после внесения правки в модуль — поставить статус `DIRTY` в его файле сигнатуры. Пересборку сигнатуры (переход обратно в `CLEAN`) агент **не делает сам** в рамках обычной работы — она запускается командой `/c сигн` (отдельно) или происходит автоматически внутри `/c push` / `/c синхрон` перед коммитом.

5. Не заводить сигнатуру для модуля, который активно переписывается в рамках текущей задачи — сначала стабилизировать код.

## Что не делать

- Не читать полный код модуля "на всякий случай", если сигнатура `CLEAN` и вопрос не требует правки.
- Не пропускать пометку `DIRTY` после правки.
- Не пересобирать сигнатуру самостоятельно, по своей инициативе — только через команду `/c` (сценарии `сигн`, `push`, `синхрон`).
