# Правила и опыт

> Только короткие императивные правила (≤2 строк). Формат: `[Контекст] Признак -> Действие`. Не логи, не разборы, не скрипты.


## Терминалы Windows

- `[cmd.exe]` В конвейерах используй `findstr` (не `Select-String`/`grep`), цепочки — через `&&`; вывод кириллицы — OEM (кракозябры), поэтому ищи ASCII-маркеры (`p-any`, `presets`), а не русские слова.
- `[cmd.exe]` «…не является внутренней или внешней командой» на PowerShell-командлет (`Copy-Item`) = сессия фактически cmd.exe, несмотря на Default Shell. -> Переходи на cmd-синтаксис (`copy`) или явно вызывай `powershell -NoProfile -Command`.
- `[PowerShell 5.1]` Скрипт .ps1 без BOM читается как ANSI, и кириллица в строковых литералах ломает парсинг (ParserError). -> Держи .ps1 ASCII-only либо UTF-8 с BOM; сравнения с кириллицей выноси в VBA.
- `[PowerShell/COM]` Неподавленный вывод COM-вызова (`$qt.Refresh($false)`) утекает в результат функции и превращает её возврат в массив. -> Перед каждым COM-вызовом в функции ставь `$null = ...`.

## Инструменты и поиск

- `[search_files]` Поиск кириллических паттернов регистрозависим: «постановк» не находит «Постановка» в заголовках. -> Проверяй оба регистра или пиши `[Пп]остановк`.
- `[Режимы]` В Architect-режиме нет `execute_command` — терминальные операции (git, PowerShell) недоступны. -> Для commit/push и команд ОС переключайся в Code через `switch_mode`.
- `[apply_diff]` Много-блочный дифф может примениться частично («unable to apply all diff parts»), остальные блоки молча не применяются. -> После такого ответа перечитывай изменённые области файла и доноси недостающее отдельными диффами.

## VBA

- `[VBA/имена]` Переменная с именем ключевого слова/функции VBA (`tab` vs `Tab`, `j` vs `J`) даёт «Compile error: Syntax error» только при первом вызове процедуры (ленивая компиляция) и выглядит как зависание Excel. -> Не называй переменные именами функций/ключевых слов VBA; при внезапном Compile error ищи такой конфликт.
- `[VBA/импорт .bas]` VBE читает .bas только в ANSI: импорт UTF-8 файла превращает кириллицу в «?» без единой ошибки. -> Перед Import File перекодируй UTF-8 → ANSI 1251 (PowerShell-командой).
- `[VBA/Dictionary]` Присвоение объекта в `Scripting.Dictionary` через Let (`d(k) = obj`) даёт runtime-ошибку с пустым описанием (Err 0). -> Объекты в Dictionary клади только через `Set d(k) = obj`.
- `[VBA/ByRef]` Элемент Variant-массива не передаётся в `ByRef Double`-параметр («ByRef argument type mismatch»). -> Оборачивай на месте вызова: `Fmt(CDbl(v(0)))`.
- `[VBA/массивы]` `ReDim Preserve` не меняет нижнюю границу (`ReDim x(0 To 0)` → `Preserve x(1 To n)` — ошибка). -> Двухпроходный отбор: сначала подсчёт, затем один `ReDim x(1 To n)`.

## Сборка и Excel

- `[Excel/книги]` Переименование/удаление build-книги даёт IOException «файл используется» — сборочный скрипт оставляет EXCEL.EXE открытым (в нём нет Quit). -> Перед манипуляциями с книгой: `Stop-Process -Name EXCEL -Force`.
- `[Excel/сборка]` build-report-mto.ps1 в режиме «продолжить» пропускает модули, уже существующие в книге по имени, — пересборка не обновляет изменённые `.bas`. -> Обновление модуля в существующей build-книге: Remove+Import через COM + `Save()`, а не повторный запуск сборки.
- `[Excel/автоматизация]` MsgBox VBA-процедуры, вызванной через COM Run, блокирует вызов до закрытия; SendKeys без активации окна в диалог не попадает. -> Фоновый job: `$wsh.AppActivate($pidExcel)` → `SendKeys "{ENTER}"` с паузами.
- `[Excel/COM-импорт]` Remove+Import модуля без `$wb.Save()` до Run теряется при падении скрипта — книга молча исполняет СТАРЫЙ код, и новые правки «не действуют». -> После переимпорта всегда `$wb.Save()`, только потом Run; факт версии проверяй чтением `CodeModule.Lines`.
- `[Excel/диагностика]` «Зависание» COM-прогона = модальный диалог VBA (Compile/Run-time error) или VBE в Break. -> Перечисляй окна процесса EXCEL.EXE через user32 `EnumWindows` (заголовок диалога) и `VBE.ActiveCodePane.GetSelection` (текущая строка).

## Git

- `[Git]` Push отклоняется «fetch first», когда remote ушёл вперёд. -> `git fetch` + `git merge origin/main --no-edit` (rebase не использовать — зависает на этой машине), затем push.
- `[Git]` Файл показан в `git status` как `??` — это новый недобавленный файл, а не игнор: игнорируемые в status не выводятся. -> Проверять игнор только `git check-ignore -v`.
- `[Git]` Цепочка `git status ... ; git diff --stat` дала «unknown option `stat'» — флаги второй команды попали в первую. -> Выполняй git-команды по одной, без цепочек через `;`.

## Документация

- `[docs/актуальные]` В актуальных .md не ссылайся на архивные документы («§5.1 постановки», «Приложение 2 ТЗ») — встраивай реальный текст требования; ссылка на архив уместна только для указания происхождения документа.

## ReportMTO (специфика проекта)

- `[ReportMTO/контракт Core]` Сигнатуры `ParseAIResponse`/`BuildPlaceholders` (3 позиционных параметра) зашиты в modMain.bas. -> Расширение числа слайдов/ИИ-выводов — только через module-level кэш (как `mPairs`), сигнатуры не менять.
- `[ReportMTO/modAggregate]` Фильтр `col@=a;b;c` режет список по `;`. -> Значения `Variable` с разделителем `+` (`СТК+ПРК`) перед фильтром нормализуй `Replace("+",";")` + `Trim`, иначе фильтр тихо не совпадает.
- `[ReportMTO/недели]` Арифметика «номер недели − N» ломается на границе года (P1-4). -> Окна/периоды строй только по упорядоченным `yearWeek` (year_status*100+week_status), реально присутствующим в данных.
