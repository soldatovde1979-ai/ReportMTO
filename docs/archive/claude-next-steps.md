## 1. Что сделано в этой ревизии (Спринты 1–2 ревью — ЗАКРЫТО в коде)

Правки внесены в исходники; **в реальном Excel не компилировались и не прогонялись** —

### 1.1 P0 — блокировали запуск (6 из 6 закрыто)

- [x] **P0-1** `modAggregate`: массивы приняты как `Variant` (VBA не допускает `Optional`-массивы
      и требует точного совпадения типа) — иначе `ByRef argument type mismatch` на каждом из 12 вызовов.
      Заодно закрыт P2-1: карта «имя колонки → индекс» строится один раз в `BeginSnapshot`.
- [x] **P0-2** Результат `ParseAIResponse` доходит до отчёта: `BuildPlaceholders(slide3, slide4, slide5)`.
      Раньше отчёт **всегда** собирался с заглушками, даже при корректном ответе провайдера.
- [x] **P0-3** `modHTMLEngine` читает и пишет строго UTF-8 (`ADODB.Stream`), запись — без BOM.
      Было: чтение UTF-8-шаблона как UTF-16 и запись результата в UTF-16.
- [x] **P0-4** Двухшаговый разбор ответа Chat Completions: `content` → `JsonUnescape` → три ключа.
      Добавлены `response_format: json_object` и `temperature: 0.2`.
- [x] **P0-5** В промпт уходят реальные агрегаты (JSON, белый список полей), а не первая строка
      сводной (`in_bounds; (Все);`).
- [x] **P0-6** Типизация в M (`fnNormalizeFields`, контракт `table → table`, culture `en-US`) —
      без неё `deltaHours` не считался никогда, а `BuildSyncPairs` падал с `Type mismatch`.

### 7.2 Реальный прогон сборки — найденные баги (закрыто)

- [x] **Баг `prmSourcePath`**: это обычная Power Query query (`ThisWorkbook.Queries`), а не
      именованный диапазон Excel. Исправлено на `SetSourcePathParameter`.
- [x] **Баг №1 сборки**: `$wb.Workbooks.Open()` падал с `COMException` — снималось стандартным
      чек-листом Excel-automation (не «от имени администратора», нет зависшего `EXCEL.EXE`,
      файл не заблокирован как «скачанный из интернета»).
- [x] **Баг №2**: `VBProject` кэшируется один раз после `SaveAs`; каждый `Import` в своём `try/catch`.
      Если ошибка повторяется — вероятная причина в групповой политике, сбрасывающей `AccessVBOM`.
- [x] **Баг №3 (важный)**: `.bas`-импорт всегда читает файл в системной ANSI (Windows-1251),
      а не UTF-8 → побитая кириллица, включая строковые литералы промпта. Скрипт перекодирует
      файл во временную ANSI-копию перед импортом; исходники остаются в UTF-8.
- [x] **Баг №4**: `"$Description:..."` в PowerShell → `${Description}:`.
- [x] **Стандарт**: все `.ps1` сохраняются с UTF-8 BOM (Windows PowerShell 5.1 без BOM читает
      файл как ANSI); `.bas` и `.pq` — UTF-8 без BOM.
- [x] Опубликована наглядная схема «Архитектура ReportMTO» — держать в актуальном виде вместе
      с правками Core/Content Spec (после перехода на `modAggregate` схему нужно обновить:
      ветка PivotTable из потока МТО ушла).
