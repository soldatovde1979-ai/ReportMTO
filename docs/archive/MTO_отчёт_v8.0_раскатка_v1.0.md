# Отчёт МТО v8.0 — перевод на шаблон v4.0 (8 слайдов)

## Что сделано

**Задача:** «привести в соответствие с макетом, допиши код, результат должен быть
неотличим». Эталон — `temp/MTO_макет_отчета_v4.0.html`, шаблон —
`temp/tmp_index_v4.0.html` (59 плейсхолдеров), контракт —
`docs/plans/MTO_контракт_шаблона_v1.0.md`.

Написан код, заполняющий все 59 плейсхолдеров.

| Модуль | Версия | Что делает |
|---|---|---|
| `modContentZone` | 2.0, ~3640 строк | слайд 1 (обзор недели) и слайды 5-8 (техника): 38 плейсхолдеров + примитивы разметки и графики для всего отчёта |
| `modContentDisc` | 1.0, ~775 строк, НОВЫЙ | слайды 2-4 (дисциплина): 13 плейсхолдеров |
| `modContentMTO` | 8.0 | оркестратор: шапка, подвал, выводы ИИ, сборка словаря; контракт Core не менялся |

Разметка снята с эталона: классы, геометрия SVG, тексты пояснений под блоками.
Собственных классов не изобретено — только словарь контракта.

## Решения, принятые по ходу

- **Слайд 1 отнесён к части «Техника».** В эталоне у него чип «трек Б, единица
  счёта — заказ-наряд», и семь из восьми плиток KPI считаются по нарядам. Он живёт
  в `modContentZone`, а не в модуле дисциплины.
- **Неделя считается в VBA из поля `date`, а не берётся из колонки `yearWeek`.**
  Причина: в продуктивной книге `yearWeek` равен нулю во всех 136 108 строках —
  Power Query в книге старше `src/powerquery/` и собирал неделю из полей, которых
  выгрузка 2026 года больше не отдаёт. Ось времени умирала молча. Своя ISO-неделя
  (`IsoYearWeek`) снимает зависимость. Для слайдов 1-4 в `modContentMTO.WeeksList`
  добавлен запасной путь: если в колонке нет ни одной осмысленной недели, ось
  берётся из даты создания наряда, и факт пишется в лог.
- **Классификатор дефектов перенесён в VBA** (`tools/mockup_v1.0/classify.py` →
  `modContentZone.BuildRules`): два уровня, правила узла привязаны к группе
  дефекта. Остаток «(не классифицировано)» показывается числом, а не прячется.
- **Возвраты**: окно 30 суток, отсчёт от `zn_closed` предыдущего наряда, возврат
  относится к периоду ПЕРВОГО наряда, только ближайший возврат, только внеплановые.
  Три уровня строгости: по группе / по подкатегории / по подкатегории и только по
  отказам. Периоды, у которых окно ещё не истекло, приглушены и вынесены за
  пунктирную границу.
- **Core не тронут.** Шкала цвета рамки процента (0/50/75/100) реализована в
  `modContentMTO.PctBorderColor` через `modColor.InterpolateHex`; сам `modColor`
  остался трёхточечным.
- **Старые построители слайдов 1-4 в `modContentMTO` (v <= 7.4) больше никем не
  вызываются, но не удалены** — решение об удалении за автором проекта.

## Что требует решения

1. **`BLOCK_POSTS_*`, «С планшета»** — единица счёта наряд, а определения
   «наряд подписан с планшета» в исходниках нет. Принято: наряд считается «с
   планшета», если ВСЕ подписи этой дирекции по нему за отчётную неделю
   поставлены с планшета. Подтвердить или заменить.
2. **`BLOCK_PEOPLE_*`, «Ср. время»** — принято: среднее «приёмка → выбытие» по
   нарядам, где сотрудник подписал выбытие (это же определение, что и в
   `deltaHours` версии 7.4). Подтвердить.
3. **`шхКлассификаторДефекта`** — есть ли у справочника подчинённые уровни. Если
   есть, текстовый классификатор надо заменить на них: справочник авторитетнее
   разбора описаний. Сейчас остаток без узла — около 25 %.

## Как раскатать

Из корня проекта, книга должна быть закрыта:

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\apply_v8.0.ps1
```

Скрипт вызывает `install\install.ps1` (VBA-модули, Power Query из
`src\powerquery`, шаблон `tmp_index.html`) и `tools\compile_check.ps1`
(принудительная компиляция VBA на временной копии).

**После установки обязательно перезагрузить JSON в книге** — обновлённый M-код
должен пересобрать `tbDATA`, иначе `yearWeek` останется нулём и слайды 1-4 будут
работать через запасной путь.
