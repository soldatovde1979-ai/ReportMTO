## 1. Новые ключи Variable (все с дефолтами)

| Ключ | Значение по умолчанию | Назначение |
|---|---|---|
| `REPORT/WEEK` | пусто/`0` = авто | отчётная неделя (ПН); явное число = номер недели в последнем году, где она встречается в данных (см. ниже и §5) |
| `REPORT/MIN_POST_RECORDS` | `10` | порог «мало данных» в оценке Блока 2 |
| `REPORT/SLIDE_ZONES` | `СТК+ПРК` | набор ремзон второго экземпляра Блока 1 на слайдах дирекций (разделитель `+`; перед фильтром нормализуется в `;`, см. §5.2); пусто = не выводить |
| `NormaForPlanshet` | `90` | порог «норма» Блока 2 |
| `ProvalForPlanshet` | `50` | порог «провал» Блока 2 |

Существующие ключи (`REPORT/WEEKS_WINDOW`, `REPORT/TOPN`, `REPORT/MIN_RECORDS`, `REPORT/SYNC_THRESHOLD_MIN`) продолжают использоваться.

Семантика `REPORT/WEEK` (пакет A, см. §5):

- **авто** (пусто/`0`): второй с конца `yearWeek`, реально присутствующий в данных, — без календарной арифметики недель (граница года, P1-4);
- **явное число N** (1…50): берётся последний год, в котором неделя N встречается в данных.

## 2. Состав работ (порядок по приоритетам; нумерация — по разделу 5 целевого документа)

3. **П.3 — Блок 1:** параметры «Дирекция» и «Ремзоны»; окно — последние 8 значений `yearWeek`, присутствующих в данных, не превосходящих отчётную неделю (см. §5.3).

6. **П.7 — Блок 7:** добавить «10 аномалий» — топ-10 нарядов с максимальным расхождением `status_date` «Готов к выбытию» между ДГМ и ДЭНТ (выводить: номер ЗН, пост, даты-время обеих дирекций, разница «чч:мм»).
7. **П.8 — Блок 9а:** строки — вид ремонта (`zn_type`, срез `defekt_type`), колонки ДГМ / ДЭНТ, значение — «% планшет».
8. **П.9 — Презентация:** пересборка [`tmp_index.html`](../../tmp_index.html:1) под 7 слайдов (Обзор; ДЭНТ; ДГМ; Синхронность; Дефекты и рейтинг; Динамика по дирекциям; Динамика по постам). Плейсхолдеры: `{{DASH_1_YTD}}`, `{{DASH_1_PREV}}`, `{{BLOCK_2_PREV}}`, `{{BLOCK_2_CHART}}`, `{{BLOCK_1_DENT_ALL}}`, `{{BLOCK_1_DENT_ZONES}}`, `{{BLOCK_1_DGM_ALL}}`, `{{BLOCK_1_DGM_ZONES}}`, `{{BLOCK_6_DENT}}`, `{{BLOCK_6_DGM}}`, `{{BLOCK_7_TABLE}}`, `{{BLOCK_8_TABLE}}`, `{{BLOCK_9_TABLE}}`, `{{BLOCK_9A_TABLE}}`, `{{BLOCK_6_RATING}}`, `{{BLOCK_4_TABLE}}`, `{{BLOCK_5_TABLE}}` + `{{AI_INSIGHT_SLIDE_N}}` (N=1…7).
9. **П.9 — ИИ-выводы:** ключи `slide1…slide7_conclusions` в [`BuildPrompt()`](../../src/vba/modContentMTO.bas:175) и [`ParseAIResponse()`](../../src/vba/modContentMTO.bas:297). **Сигнатуры `ParseAIResponse`/`BuildPlaceholders` не менять** (контракт Core, spec.md §14): 7 ключей парсятся в module-level кэш, наружу контракт возвращает прежние 3 значения (см. §5.1). Системный промпт переписывается под 7 слайдов. **Псевдонимизация:** маппинг `employee` → неизменяемый маркер `[EMP_N]` из единого алфавитного списка всех `employee` снимка (кэш на один прогон, см. §5.6); системный промпт явно запрещает изменять/склонять маркеры; в промпт — только маркеры и агрегаты по людям (например `block6_people`: маркер, % планшет ПН и ПН-1, число подписаний); при вставке в HTML — обратная замена `[EMP_N]` на ФИО по убыванию номеров. Таблица соответствия наружу не уходит.
10. **П.1 — Расшифровка/гиперссылки:** встроенный в HTML дамп строк `tbDATA` **с ФИО** (решение заказчика) за предыдущую и текущую недели (отбор по `yearWeek`); поля: `number`, `date`, `ready_for`, `direction`, `status_date`, `arm`, `post`, `postN`, `employee`; сериализация дампа — `JsonEscape` (+ `«<»` → `\u003c`), НЕ `HtmlEscape` (см. §5.4); клик по цифре блока раскрывает относящиеся строки; визуально цифры — как текст. Это самый объёмный пункт постановки.
11. **П.10 — График:** столбики по Блоку 2 (посты × «% планшет» или нарядов) — офлайн, инлайн-SVG/JS, без внешних библиотек.
12. **П.13 — Описания расчёта:** под каждым блоком на слайде — краткая подпись «как считается» (фильтр/формула), тексты — из разделов 2–3 целевого документа, формулируются по фактической логике реализации (окно по `yearWeek`, нормализация зон `+`→`;`, состав набора медианы и т.п.).
13. **П.11 — Терминология:** все сравнения статусов — через `NormStatus` («ё»→«е»), «Готов к приёмке»/«Готов к выбытию».

## 5. Архитектурные ограничения (как именно реализовывать)

Раздел закрывает конфликты, которые иначе приводят к неберущейся сборке или тихому неверному отчёту. Все пункты обязательны.

### 5.1 Контракт `ParseAIResponse`/`BuildPlaceholders` vs 7 слайдов

`modMain.bas` вызывает `ParseAIResponse(responseText, slide3, slide4, slide5)` и `BuildPlaceholders(slide3, slide4, slide5)` — ровно 3 позиционных параметра, сигнатуры зафиксированы контрактом Core (spec.md §14). Менять сигнатуры запрещено (§4).

Реализация — паттерн module-level кэша, как `mPairs`/`mPairsReady` в `BuildSyncPairs`:

- завести `Private mInsights As Object` и `Private mInsightsReady As Boolean`;
- `ParseAIResponse` парсит ВСЕ 7 ключей `slide1…slide7_conclusions` и складывает их в `mInsights`; через `ByRef slide3/4/5` наружу возвращаются прежние 3 значения (slide3/4/5 или заглушки `AI_FALLBACK`) — они дальше не используются;
- `BuildPlaceholders` читает `AI_INSIGHT_SLIDE_1…7` из `mInsights`, если `mInsightsReady`; иначе — fallback на входные параметры (нужно для `DebugGenerateOffline`, который вызывает `BuildPlaceholders(STUB, STUB, STUB)` без `ParseAIResponse`);
- сброс кэша `mInsights`/`mInsightsReady` — в `BuildPivots` и `EnsureSnapshot` вместе с `mPairsReady`;
- системный промпт в `BuildPrompt` переписывается под 7 слайдов (сейчас он требует 3 ключа).

### 5.2 `REPORT/SLIDE_ZONES`: нормализация разделителя `+` → `;`

Фильтр `modAggregate` «входит в список» (`col@=a;b;c`) режет значение по `;`, а ключ по умолчанию — `СТК+ПРК` (разделитель `+`). Перед передачей в фильтр обязательна нормализация `Replace(zones, "+", ";")` + `Trim` каждой части. Без неё `Split` вернёт один элемент `СТК+ПРК`, фильтр не совпадёт ни с чем, и вторая матрица Блока 1 на слайдах ДЭНТ/ДГМ молча станет пустой — без единой ошибки в логе. Пустое значение ключа = экземпляр не выводить.

### 5.3 Окно Блока 1: только по присутствующим yearWeek

Окно «8 недель от отчётной недели» = последние 8 значений `yearWeek`, реально присутствующих в данных, отсортированных численно, не превосходящих отчётную неделю (паттерн `BuildBlock3KPI`). Арифметика «номер недели − 7» запрещена — она ломается на границе года (закрытый класс дефекта P1-4).

### 5.4 JSON-дамп расшифровки: `JsonEscape`, не `HtmlEscape`

Дамп сериализуется `JsonEscape` (полное экранирование, уже есть в модуле) + замена `«<»` → `\u003c`; `HtmlEscape` не применяется — HTML-сущности внутри `<script>` не декодируются, и `JSON.parse` сломается. В остальном HTML (таблицы, выводы ИИ) правило `HtmlEscape` из §4 остаётся в силе.

### 5.5 Медиана `deltaHours`: поверх кэша `mPairs`

Публичный API `modAggregate` медиану не даёт, `RowMatchesFilters` приватна. Медиана считается по `mPairs` из `BuildSyncPairs` (deltaHours уже посчитан): набор = ЗН со статусом «Готов к выбытию» в обеих дирекциях. Ручной проход `RowCount`/`CellRaw` с копией базового фильтра не требуется. // TODO: `BuildSyncPairs` остаётся второй ручной копией базового фильтра (после `IsTrueText`/`NormStatus`) — техдолг, зафиксирован.

### 5.6 Псевдонимизация `employee`

- единый канонический список: `modAggregate.DistinctValues("employee", FBase())`, сортировка по алфавиту, кэш на один прогон (сброс вместе с `mPairsReady`); один человек получает один номер во всех частях промпта и ответа;
- маркер — неизменяемый токен `[EMP_N]`, а не русское слово «Сотрудник N» (склоняется); системный промпт явно запрещает изменять маркеры;
- обратная замена `[EMP_N]` → ФИО — только в тексте ИИ-выводов, по убыванию номеров (иначе `[EMP_1]` зацепит `[EMP_12]`); ФИО перед вставкой в HTML — через `Esc`.

### 5.7 Валидация порогов Блока 2

При чтении `NormaForPlanshet`/`ProvalForPlanshet`: если `ProvalForPlanshet ≥ NormaForPlanshet` — текстовая оценка не выводится и в лог пишется предупреждение о некорректной конфигурации `Variable`.

## 6. Критерии приёмки

- Чек-лист [`content-spec.md` §11](../specs/content-spec.md:399) выполняется полностью.
- Новые: ключи `Variable` читаются с дефолтами; отчёт собирается на 7 слайдов; выводы `slide1…slide7` реально попадают на слайды (при успешном ответе DeepSeek); маркеры `[EMP_N]` заменяются на ФИО; клик по цифре раскрывает строки за две недели (с ФИО); рейтинг — за отчётную неделю; медиана — «чч:мм»; в Блоке 7 — топ-10 аномалий; график по Блоку 2 рендерится офлайн; у каждого блока — подпись с описанием расчёта.
- Блок 1: окно — ровно последние 8 присутствующих `yearWeek` ≤ отчётной недели; второй экземпляр по `REPORT/SLIDE_ZONES` содержит только перечисленные зоны (`+` нормализуется в `;`); пустой `SLIDE_ZONES` не выводит экземпляр.
- Контракт: сигнатуры `ParseAIResponse`/`BuildPlaceholders` не изменены (3 параметра); `DebugGenerateOffline` продолжает собирать отчёт со STUB; кэш `mInsights` сбрасывается в `BuildPivots`.
- Прогон с недоступным ИИ (STUB) не содержит протухших выводов предыдущего прогона.
- Проверить прогоном на тестовом JSON (в т.ч. граничные случаи: пустой `post`, >2 статусных записей, ЗН только в одной дирекции).
