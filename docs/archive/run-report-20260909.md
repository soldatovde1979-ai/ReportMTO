# Брифинг: автономный прогон формирования отчётов (09.09.2026, обеденное время)

> Задача от пользователя: запустить книгу, запустить формирование отчётов; при проблемах —
> сразу чинить код, заливать в Excel и перезапускать. Цикл до готового отчёта к утру.
> Исполнитель — Code-режим (Architect не имеет execute_command).

## Допущения (пользователь отошёл; исправить при возвращении)

1. Рабочая книга = [`build/ReportMTO v7.0.xlsm`](build/ReportMTO v7.0.xlsm) (открыта в редакторе,
   её лог — [`build/ReportMTO_log.txt`](build/ReportMTO_log.txt:1), запись о формировании сегодня в 10:29).
   Книга «вне репозитория» с 136108 строками из [`docs/tasks.md`](docs/tasks.md:48) считается этой же.
2. «Презентация» = готовый HTML-отчёт в `result\`. PowerPoint код не генерирует
   ([`docs/spec.md`](docs/spec.md:42), слой 6 — только HTML в `result/`). Если нужен PPTX — это
   отдельная задача, вне Excel; по возвращении пользователя уточнить.
3. Данные для отчёта уже лежат в `tbDATA` книги. Если `tbDATA` пуста — источником будут JSON-выгрузки
   из `examples\` (в `data\` выгрузок нет), и нужен шаг «Загрузить» (`LoadSourceFile`).
4. Ключ ИИ: провайдер в листе `Variable` книги — источник истины. Ключ Anthropic из
   [`data/api_claude.md`](data/api_claude.md:1) используем только если провайдер в книге — Anthropic.
   Если провайдер DeepSeek, а ключа DeepSeek нет (env `AI_API_KEY` / `%APPDATA%\ReportMTO\deepseek.key`
   / Variable) — ИИ-слой уйдёт в заглушки (штатная деградация), это зафиксировать и довести отчёт
   до конца, вопрос ключа — пользователю по возвращении.

## Критерий успеха

- В `result\` появился свежий `Report_YYYYMMDD_HHMMSS.html`, собранный без ошибок в
  `ReportMTO_log.txt`, все 9 блоков и слайды заполнены (ИИ-выводы или явные заглушки).
- Все правки кода — только в `src\` + переимпорт в книгу; книга после каждого шага сохраняется.

## Порядок (исполнение)

1. **Окружение.** Перечислить окна процессов EXCEL.EXE (`EnumWindows`) — чужой Excel с книгами
   не убивать; свой COM-экземпляр создавать отдельно. Проверить наличие
   [`build/ReportMTO v7.0.xlsm`](build/ReportMTO v7.0.xlsm), [`build/tmp_index.html`](build/tmp_index.html:1)
   (обязателен рядом с книгой — `ThisWorkbook.Path`), папки `result\`.
2. **Бэкап.** Копия книги в `bak\` (вне git) до любых правок.
3. **Диагностика книги через COM** (невидимый/видимый Excel): лист `Variable` (AI/PROVIDER,
   AI/ENDPOINT, AI/MODEL, REPORT/*, OUTPUT/RESULT_FOLDER), значение `prmSourcePath`, наличие
   таблицы `tbDATA` и число строк. Записать в лог-отчёт.
4. **Ключ ИИ.** Проверить env `AI_API_KEY` и `%APPDATA%\ReportMTO\deepseek.key`; сопоставить
   с провайдером из Variable. Правило: ключ в книге не хранить, в лог не писать.
5. **Прогон 1 — DebugGenerateOffline** (без ИИ): проверить, что конвейер VBA+M+HTML цел.
6. **Прогон 2 — GenerateReport**: полный прогон через COM `Run` (или SendKeys на кнопку, если
   нужен диалог выбора файла). Мониторить `ReportMTO_log.txt` и окна Excel; модальные диалоги
   VBA не должны висеть вечно (watchdog/таймаут).
7. **Цикл исправлений.** Каждая ошибка: root-cause по логу/окну диалога → точечная правка в
   `src\vba\*.bas` или `src\powerquery\*.pq` → перекодировка UTF-8→ANSI (1251) → Remove+Import
   модуля в книгу через COM → `$wb.Save()` → повторный прогон. До зелёного критерия успеха.
   Известные грабли из [`docs/rules.md`](docs/rules.md:23): ByRef-массивы, VBA-имена, Attribute-строка
   в сравнениях, регистр имени `tbDATA`, «-2147221502» при обращении к `year_status`.
8. **Не трогать** без явного решения владельца (открытые вопросы из
   [`docs/tasks.md`](docs/tasks.md:42)): HasColumn ByVal, norm_status развилка, парсер фильтров,
   допущение ретеншна. Если прогон упрётся в один из них — остановиться, зафиксировать, не изобретать.
9. **Финал.** Обновить [`docs/tasks.md`](docs/tasks.md:1); при новой ошибке — +1 строка в
   [`docs/rules.md`](docs/rules.md:1) (лимит 40 строк). Отчёт о результате пользователю.
