## Задача 1. [`src/vba/modLog.bas`](src/vba/modLog.bas:1) — новая семантика DEBUG, фильтр листа Logs, расширение .log

1.1. [`GetDebugLevel()`](src/vba/modLog.bas:19) — оставить чтение ключа `DEBUG` с листа Variable, default `0` (ключа нет → 0).

1.2. Семантика уровня `DEBUG` (согласовано с владельцем):
- **Лист `Logs` книги** — всегда только записи типов **«Веха»** и **«Ошибка»**. Записи «Инфо», «Предупреждение», «Отладка» в лист не пишутся никогда.
- **Внешний файл рядом с книгой**:
  - `DEBUG=0` — файл не пишется;
  - `DEBUG=1` — в файл пишутся только «Ошибка» и «Веха»;
  - `DEBUG=2` — в файл пишутся все записи (включая «Инфо», «Предупреждение», «Отладка»).

1.3. Реализация в [`WriteLogEntry()`](src/vba/modLog.bas:33):
- Ввести новый тип записи «Веха» (entryType). Схема листа Logs (5 колонок) НЕ меняется.
- Фильтр для листа: добавлять строку в tbLogs только если entryType = «Ошибка» или «Веха».
- Запись во внешний файл НЕ зависит от записи в лист: «Инфо»-записи при `DEBUG=2` должны попадать в файл, даже если в лист не пишутся.
- Сигнатура `WriteLogEntry` сохраняется (её вызывают все модули); добавление отдельной процедуры-обёртки `WriteMilestone(...)` с типом «Веха» — на усмотрение разработчика.

1.4. [`AppendToFile()`](src/vba/modLog.bas:61):
- Путь: `ThisWorkbook.Path & "\ReportMTO_log.txt"` → `ThisWorkbook.Path & "\ReportMTO.log"`.
- Фильтр по `DEBUG` и типу записи согласно 1.2.

1.5. [`WriteDebug()`](src/vba/modLog.bas:28): механика `minLevel` сохраняется; тип «Отладка» в лист не пишется (общий фильтр), в файл — только при `DEBUG=2` (существующая проверка minLevel это уже обеспечивает).

1.6. Запрещено: менять контракт листа Logs, менять поведение при отсутствии листа/защите (Silent-обработчик), писать API-ключи в лог.

## Задача 2. [`src/vba/modMain.bas`](src/vba/modMain.bas:1) — вехи, манифест очереди, трассировка DEBUG=2

2.1. Перевести записи «было/стало» в тип «Веха»:
- [`LoadSourceFile()`](src/vba/modMain.bas:29): «Строк до: X; строк после: Y» и «Загрузка завершена. Строк в tbDATA: N» — тип «Веха».
- [`LoadPackage()`](src/vba/modMain.bas:87): «Записано N из M» — тип «Веха».
- Записи об ошибках остаются типом «Ошибка».

2.2. Манифест очереди в `LoadPackage` — ДО вызова Refresh, одной записью типа «Веха»: перечень файлов в порядке очереди: номер, имя файла, дата/время из имени (`YYYYMMDD_HHMMSS`), rec-счётчик из имени. Это реализация «записи между файлами» при однопроходной загрузке.

2.3. Трассировка `DEBUG=2` (пишется во внешний файл через `WriteDebug 2`): в `LoadSourceFile` и `LoadPackage` — вехи «старт (строк до: N)», «до Refresh», «после Refresh (X.X c)», «BuildPivots (X.X c)». Тайминги через `Timer`. Комментарий с границей: строки внутри Power Query VBA не видит, поэтому «каждая строка» заменена вехами/таймингами (максимум достижимого при одном проходе).

2.4. [`ListJsonFiles()`](src/vba/modMain.bas:128): сортировать по дате/времени, распарсенной из имени файла (`sppr_tablet_YYYYMMDD_HHMMSS_*`); если дату извлечь не удалось — сортировка по имени (fallback). Структура функции (Variant-массив путей) сохраняется.

2.5. Запрещено: трогать [`SumRecsFromNames()`](src/vba/modMain.bas:171); [`BackupWorkbook()`](src/vba/modMain.bas:223) не вызывается в `LoadPackage` — функцию НЕ удалять и не менять (в пакетной загрузке бэкап между файлами отсутствует).

## Задача 5. Объединение install/release в единый [`install/install.ps1`](install/install.ps1:1)

5.1. Объединить в один скрипт `install\install.ps1`:
- шаги установки (текущий install.ps1: бэкап → VBA-модули → PQ-запросы → шаблон → верификация);
- шаги релиза (текущий [`release.ps1`](install/release.ps1:1): хеши исходников и `release.state`, защита от отката `BUILD/VERSION`, компиляция `tools\compile_check.ps1`, версия и миграции, `install\VERSION`, CHANGELOG);
- вывод обёртки `install_prod.ps1` (печать цели и кода возврата).

5.2. Параметры единого скрипта:
- `-Target` — книга или папка; по умолчанию `.\ReportMTO.xlsm` (корневая книга);
- `-InstallOnly` — только установка и верификация, без версии/миграций/CHANGELOG (режим для build-книги и повторных установок; заменяет прежнее поведение install.ps1);
- `-DryRun`, `-Bump patch|minor|major`, `-Force`, `-SkipCompile`, `-ProjectRoot` — как в release.ps1.

5.3. Полный цикл по умолчанию (без -InstallOnly): если установка или компиляция вернули ненулевой код — версия не меняется, VERSION/release.state/CHANGELOG не трогаются (существующее правило).

5.4. Документация в дайджесте (п.4 ТЗ владельца): включить в `Get-SourceMap` файлы `README.md`, `docs\**\*.md`, `install\*.md` (кроме служебных `VERSION`, `release.state`). Изменения документации поднимают патч и пишутся в CHANGELOG отдельной строкой «Изменена документация: …».

5.5. Не писать запись в CHANGELOG при `RELEASE_SOURCES_SAME` (устраняет дубль версий, напр. двойной «8.1.3»).

5.6. `release.ps1` и `install_prod.ps1` после объединения перенести в `tools\archive\` (правило «заменённое — в архив»).

5.7. Сохранить маркеры вывода: `TARGET`, `RELEASE_*`, `VBA_*`, `PQ_*`, `TPL_*`, `VERIFY_*`, `COMPILE_*`, `MIG_*`, `BUILD_*`, `PATCHED`, `DONE`. Файл UTF-8 с BOM, PowerShell 5.1, `$ErrorActionPreference = "Stop"`.

## Общие ограничения (действуют для всех задач)

- Не менять: контракт листа `Logs` (5 колонок), схему `tbDATA`, лист `Variable`, `tmp_index.html`, `qDiagImport`, миграции.
- Не удалять комментарии, расчёты и алгоритмы.
- Секреты и пароли — только через ENV/плейсхолдеры; в логи не писать.
- После каждого изменения файла — отчёт: «Внесенные изменения / Намеренно не тронуто / Потенциальные риски».

## Критерии приёмки

- `DEBUG` 0/1/2 работает по таблице семантики; лист Logs содержит только «Веха» и «Ошибка».
- Файл `ReportMTO.log` создаётся рядом с книгой при `DEBUG>=1`; при `DEBUG=0` — не создаётся/не дополняется.
- В `ReportMTO.log` при `DEBUG=2` видны вехи/тайминги загрузки; манифест очереди файлов присутствует до пакетной загрузки.
- `install\install.ps1` — единая точка входа; `release.ps1`/`install_prod.ps1` в архиве; вся документация ссылается на новый путь.
- Build-книга обновлена, `COMPILE_OK`, e2e зелёный; корневая книга релизнута; загрузка всех JSON из `data` выполнена с сверкой «N из M».
