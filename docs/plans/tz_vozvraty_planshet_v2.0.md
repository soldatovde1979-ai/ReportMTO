## 1. Вопрос

Снижает ли приёмка с планшета число возвратов.

## 2. Группировка: две строки, не три и не пять

| Группа | Условие |
|---|---|
| **Есть подпись с планшета** | подпись ДЭНТ на статусе «Готов к выбытию» поставлена с АРМ `ПЛАНШЕТ` |
| **Нет подписи с планшета** | всё остальное: подпись ДЭНТ с ПК **или** подписи ДЭНТ нет вовсе |
| **Итого** | сумма двух строк |

Смотрим подпись **ДЭНТ**: из ремонта машину принимает ДЭНТ, и качество приёмки
определяет их подпись. Подпись ДГМ — это «сдал», а не «принял».

Деление на «ПК» и «нет подписи» снимается: это одна сущность — работу на месте
не приняли. Разбивать её на две строки значит сравнивать разные вещи в одной таблице.

**Что в ветке сейчас:** три строки (планшет / ПК / нет подписи). Их надо свести к двум.

## 3. Блок 1. Итог

| Подпись ДЭНТ на выбытии | Нарядов | Из них вернулись | Доля возвратов |
|---|---|---|---|
| Есть, с планшета | | | |
| Нет подписи с планшета | | | |
| **Итого** | | | |

Под таблицей — вывод, посчитанный кодом: у какой группы доля выше и на сколько
процентных пунктов. Если разрыв в пользу «нет планшета» — так и пишется, что
гипотеза на этих данных не подтверждается.

### 3.1 База (одна на все три блока)

Наряд входит, если выполнено всё:

1. внеплановый, характер работы по классификатору = «Отказ» — то же определение,
   что у главной плитки возвратов слайда 6, иначе числа между блоками не сойдутся;
2. закрыт (`zn_closed > 0`) — отсчёт окна возврата идёт от закрытия;
3. **окно возврата истекло**: `zn_closed <= конец снимка − 30 суток`.

**Пункт 3 обязателен, и вот почему.** У наряда, закрытого вчера, возврат физически
не успел случиться. Сам по себе это перекос маленький, но свежие наряды распределены
между группами **неравномерно**: планшет внедряют, и доля подписей с планшета в
последние месяцы выше. Без отсечения группа «с планшета» получит заниженную долю
возвратов, и блок «докажет» гипотезу, которую не проверял.

Число отсечённых выводится отдельной строкой под таблицей — иначе читатель не поймёт,
почему числа меньше, чем в плитках возвратов выше.

**Возврат** — машина вернулась с той же подкатегорией дефекта в течение 30 суток
после закрытия, повторный наряд тоже отказ.

## 4. Блок 2. Разрез по восьми неделям

| | нед 1 | … | нед 8 | Всего |
|---|---|---|---|---|
| **С планшета** · нарядов | | | | |
| **С планшета** · вернулись | | | | |
| **С планшета** · доля | | | | |
| **Без планшета** · нарядов | | | | |
| **Без планшета** · вернулись | | | | |
| **Без планшета** · доля | | | | |

Строки «нарядов» обязательны: на трёх нарядах доля ничего не значит, и без этой
строки таблица врала бы уверенным видом.

### 4.1 Открытый вопрос: к какой неделе относить наряд

Возврат — это пара нарядов, у неё две даты. Отнести можно:

- **к неделе создания первого наряда** — так уже ведут себя счётчики `RetPairs`,
  и недельный график возвратов на слайде 6 построен именно так. Плюс: сходится
  с соседним блоком. Минус: возврат «виден» только через месяц после ремонта;
- **к неделе закрытия первого наряда** — ближе к смыслу «когда приняли работу»,
  и именно в этот момент ставилась подпись, о которой весь блок.

**Предлагаю второй вариант** — неделя закрытия, потому что блок про момент приёмки.
Но тогда числа не сойдутся с недельным графиком возвратов выше, и это надо будет
написать в пояснении. Нужно ваше решение.

### 4.2 Ограничение, которое никуда не денется

Последние четыре недели окна почти целиком отсекаются условием «окно истекло»
(30 суток ≈ 4 недели). То есть правая часть таблицы будет пустой или почти пустой
всегда. Варианты:

- показывать 8 недель и мириться с пустым хвостом;
- сдвинуть окно назад: показывать недели с 12-й по 5-ю от конца снимка — тогда все
  восемь заполнены, но это «не последние 8 недель», и подпись должна это говорить;
- уменьшить окно возврата до 7 суток **для этого блока** — тогда отсекается одна
  неделя вместо четырёх, но определение возврата разойдётся со слайдом 6.

**Предлагаю второй вариант.** Нужно ваше решение.

## 5. Блок 3. Два года по месяцам

Таблица: столбцы — 12 месяцев, строки — группа × год, показатель — **количество
возвратов**.

| | янв | фев | … | дек | Всего |
|---|---|---|---|---|---|
| {прошлый год} · с планшета | | | | | |
| {прошлый год} · без планшета | | | | | |
| {текущий год} · с планшета | | | | | |
| {текущий год} · без планшета | | | | | |

Месяц — по той же дате, что выбрана в п. 4.1.

**График:** столбики, две серии — «с планшета» и «без планшета». Один график на год,
второй под ним, если прошлый год есть в выгрузке. Разными цветами, как в блоке
остатка по статусам.

### 5.1 Замечание, которое обязан высказать

Количество возвратов зависит от объёма группы. Если нарядов с планшетом вдвое
меньше, возвратов тоже будет меньше — и график покажет «планшет лучше» просто
потому, что группа меньше. Это не вывод, это арифметика.

**Предлагаю:** оставить количество как основной показатель (как вы просили), но
добавить под таблицей вторую, компактную — долю возвратов по тем же ячейкам.
Тогда видно и абсолют, и то, что за ним стоит. Если считаете лишним — уберу.

### 5.2 Если прошлого года в выгрузке нет

Рисуется один год и пишется прямо: «Данных за {год} в выгрузке нет». Строка нулей
не рисуется — она читается как «возвратов не было», а это неправда: это отсутствие
данных. Появится прошлый год — блоки станут сравнительными сами.

**Отдельно:** подписи с планшета в прошлом году могли не существовать вовсе, если
планшет внедрили в этом. Тогда строка «{прошлый год} · с планшета» будет нулевой
по-настоящему, и это надо отличать от отсутствия данных. Блок проверит: если за
прошлый год есть наряды, но ни одного с планшетом — так и напишет.
