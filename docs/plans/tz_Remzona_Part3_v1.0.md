## 3. Контекст: текущая архитектура (проверено по коду 14.09.2026)

**Запись наряда `mZn`** ([`modContentZone.bas:62`](../src/vba/modContentZone.bas:62)) хранит:
`Z_DATE` (создание), `Z_VEH` (`vehicle_number`), `Z_VGROUP` (`vehicle_group`), `Z_DEFEKT`
(`defekt_type`), `Z_DESC` (`defect_desc`), `Z_ACCG`/`Z_ACCD` («Готов к приемке» ДГМ/ДЭНТ,
дата подписи), `Z_LEVG`/`Z_LEVD` («Готов к выбытию» ДГМ/ДЭНТ), `Z_CLOSED`, `Z_PARTS`
(`cost_parts`). Чтение опциональных полей — через `modAggregate.HasColumn` +
`CellRaw`/`CellText` (образец: `hasParts`, [`modContentZone.bas:186`](../src/vba/modContentZone.bas:186)).

**В `mZn` пока НЕ читаются:** `cost_Trudozatrat` (фактические часы, поле уровня наряда)
и `hourdlit` (плановая длительность ремонта, часы) — добавить два поля записи
(`Z_TRUD`, `Z_PLAN`) с проверкой `HasColumn`, по образцу `Z_PARTS`.
⚠️ `cost_Trudozatrat` — часы, а не рубли ([`docs/specs/data.md:136`](../specs/data.md:136)).

**Повторы** — [`BuildRepeats()`](../src/vba/modContentZone.bas:2142): пары внеплановых
нарядов одной машины с той же группой дефекта, интервал между датами создания ≤30 сут.
Словарь `byK`: ключ `vehicle|defekt` → наряды, пары перебираются по дате.

**Простой** — [`BuildTimeHist()`](../src/vba/modContentZone.bas:3448): для каждого наряда
обе пары «приёмка→выбытие» (`Z_LEVG−Z_ACCG` и `Z_LEVD−Z_ACCD` в часах) считаются
отдельными значениями. Единица — «наряд × дирекция».

**Фазы** — [`BuildPhases()`](../src/vba/modContentZone.bas:2410): медианы фаз по неделям
окна 8 недель: постановка (создание→приёмка), ремзона (приёмка→выбытие), закрытие
(выбытие→`zn_closed`). NoteBlk уже называет фазу «постановка» отдельной полосой.

**Словарь плейсхолдеров** — `FillZonePlaceholders`
([`modContentZone.bas:3086`](../src/vba/modContentZone.bas:3086)). Новые ключи
регистрировать там же.

**Шаблон** — слайды свёрстаны в [`tmp_index.html`](../tmp_index.html:221) (одна длинная
строка); корневой и [`build/tmp_index.html`](../build/tmp_index.html:221) идентичны.

## 4. Задачи

### П1. «Кто чаще заезжает на повторный и какими поломками»

- **Вход:** `mZn` (машина, группа дефекта, даты); логика пар — как в
  [`BuildRepeats()`](../src/vba/modContentZone.bas:2142) (внеплановые, интервал ≤30 сут,
  та же машина + та же группа дефекта). Пары не пересчитывать дублирующим кодом —
  вынести общий перебор в приватный помощник либо повторить правило точечно.
- **Выход 1** — таблица «Топ машин по числу повторных заездов»: колонки
  «Машина» / «Повторных пар» / «Группы дефектов (через запятую)» / «Последний интервал, сут».
  Топ-10 по числу пар, сортировка по убыванию.
- **Выход 2** — горизонтальные бары «Повторы по группам дефектов»: топ-10 групп
  `defekt_type` по числу повторных пар + подпись всего пар.
- **По два экземпляра (R2):** плейсхолдеры `BLOCK_REPEAT_TOP_VEH_YTD`,
  `BLOCK_REPEAT_TOP_DEF_YTD` (с начала года — весь снимок) и `BLOCK_REPEAT_TOP_VEH_WK`,
  `BLOCK_REPEAT_TOP_DEF_WK` (за отчётную неделю; для пары засчитывается, если второй
  наряд пары создан на отчётной неделе: `Z_WEEK = ZoneReportWeek()`).
- NoteBlk каждого блока: поля, алгоритм (правило пары), период, оговорка
  «группа дефекта крупная — верхняя граница кандидатов» (как в существующем BuildRepeats).

### П2. «Сколько машина стояла и сколько трудочасов списано»

- **Вход:** `mZn` + новые поля `Z_TRUD` (`cost_Trudozatrat`, фактические часы) и
  `Z_PLAN` (`hourdlit`, плановая длительность, часы). Простой — полные пары
  «приёмка→выбытие» как в [`BuildTimeHist()`](../src/vba/modContentZone.bas:3448).
- **Агрегация:** по машине (`Z_VEH`): суммарный простой по всем полным парам её нарядов
  (часы), суммарные трудочасы (сумма `Z_TRUD` по нарядам машины), суммарный план
  (`Z_PLAN`). ⚠️ Допущение двойного счёта дирекций: у наряда может быть две полные пары
  (ДГМ и ДЭНТ); в данном блоке суммируются обе — зафиксировать в NoteBlk.
- **Выход:** сгруппированные бары топ-10 машин по суммарному простою: три серии на
  машину — «стояла, ч» (факт), «списано, ч» (`cost_Trudozatrat`), «план, ч» (`hourdlit`).
  Подпись: медиана/среднее простоя и сумма трудочасов по выборке.
- **По два экземпляра (R2):** плейсхолдеры `BLOCK_DOWN_VS_HOURS_YTD` (с начала года)
  и `BLOCK_DOWN_VS_HOURS_WK` (за отчётную неделю; в недельный экземпляр попадают наряды
  с `Z_WEEK = ZoneReportWeek()`).
- NoteBlk: поля, алгоритм, период, оговорка про пары дирекций.

### П3. «Медианы фаз и создание→приёмка по видам техники»

- **Вход:** `mZn`. Время создания→приёмки наряда = `(min(Z_ACCG, Z_ACCD) − Z_DATE) × 24`
  часов для нарядов, где хотя бы одна подпись «Готов к приемке» есть и не раньше даты
  создания.
- **Выход:** горизонтальные бары «Время от создания до приёмки, медиана по видам
  техники»: топ-10 `vehicle_group` по числу нарядов с полной приёмкой + строка «прочие»
  (R1). Для каждой группы — медиана часов + число нарядов. Подпись: общая медиана по
  всем нарядам.
- **По два экземпляра (R2):** плейсхолдеры `BLOCK_CREATE_TO_ACC_YTD` (с начала года)
  и `BLOCK_CREATE_TO_ACC_WK` (за отчётную неделю; `Z_WEEK = ZoneReportWeek()`).
- **Правка NoteBlk** [`BuildPhases()`](../src/vba/modContentZone.bas:2448): уточнить,
  что «день ремзоны» = фазы «ремзона» + «закрытие», а фаза «постановка»
  (создание→приёмка) в него не входит — машина в этой фазе ещё движется; ссылка на
  новый график по видам техники. Сами полосы фаз не менять.
- NoteBlk нового блока: поля, алгоритм (`min` подписей приёмки обеих дирекций), период
  (весь снимок), разрез топ-10 + «прочие».
