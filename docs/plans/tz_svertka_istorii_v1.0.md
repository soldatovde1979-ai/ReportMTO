# Свёртка истории tbDATA — постановка и решение v1.0

**Дата:** 29.09.2026. **Статус:** реализовано в ветке агента, в Excel не компилировалось.
**Основание:** `docs/tasks.md` → «Бэклог: Сделать свёртку БД»; презентация v2.5 §10.3
(«Понедельная свёртка истории … заменит ретеншн: глубина остаётся полной, объём таблицы
перестаёт расти линейно»); поручение владельца 29.09.2026 «доработать движок по
сворачиванию данных, без вопросов, придумай решение сам».

---

## 1. Проблема

- Ретеншн (`DATA/KEEP_WEEKS`, шаг R-1 `Query-ImportJSON`) удалял события старше окна
  **безвозвратно**. Решение владельца v2.2 — «хранить всю историю» — противоречило ему.
- Хранить всё сырьём нельзя: на 255 тыс. строк upsert одного файла шёл 5 ч 12 мин.
- Длинного тренда дисциплины в отчёте не было вовсе: матрица недель — 8 недель.

## 2. Решение

Старые события не удаляются, пока не свёрнуты в таблицу **`tbARCHIVE`** (лист
`tbARCHIVE`): одна строка на неделю и набор аналитик.

| Колонка | Смысл |
|---|---|
| `week` | ISO-неделя (год×100+неделя) даты подписи, у неподписанного события — даты создания |
| `month` | год×100+месяц той же даты |
| `direction`, `ready_for`, `arm`, `postN`, `emp_dep`, `employee`, `zn_type` | аналитики (срез отчёта) |
| `events` | событий в группе |
| `orders` | уникальных нарядов в группе (в пределах одного запуска свёртки) |
| `signed` | событий с `arm` ∈ {ПК, ПЛАНШЕТ} |
| `tablet` | событий с `arm` = ПЛАНШЕТ |
| `deltaSum`, `deltaCnt` | сумма и число `deltaHours` — среднее восстанавливается без сырья |
| `rolledAt` | когда свёрнуто |

### 2.1 Порядок (почему ничего не теряется)

1. `modRollup.RollupBeforeLoad` — вызывается из `LoadSourceFile` и `LoadPackage` **до** Refresh.
2. Отсечка считается тем же правилом, что ретеншн R-1: понедельник недели последней даты
   `tbDATA` минус (`KEEP_WEEKS` − 1) недель; опорная дата строки — max(`status_date`, `date`).
3. В архив уходят строки с опорной датой в **[водяной знак; отсечка)**. Водяной знак —
   ключ `DATA/ROLLUP_UNTIL` листа `Variable`: до этой даты история уже свёрнута.
4. Только **после** успешной записи архива знак сдвигается на отсечку.
5. Power Query (`qRollupUntil` → R-1) удаляет только строки **старше знака**.

### 2.2 Идемпотентность и отказоустойчивость

| Ситуация | Что происходит |
|---|---|
| Повторный запуск без Refresh | окно [знак; отсечка) пусто — ничего не добавляется |
| Свёртка упала | знак не сдвинут → PQ не удаляет ничего нового, данные целы |
| Refresh упал после свёртки | строки старше знака остались в `tbDATA`, в следующую свёртку не попадут (окно от знака), следующий Refresh их удалит; отчёт не считает их дважды — живые события старше знака отбрасываются в `BuildHistory` |
| В новом файле пришли события старше знака | удаляются ретеншном, в архив не попадают (как и при прежнем ретеншне) |

### 2.3 Ключи `Variable`

| Ключ | Умолч. | Смысл |
|---|---|---|
| `DATA/ROLLUP` | 1 | 0 — свёртка выключена |
| `DATA/ROLLUP_UNTIL` | нет | водяной знак, пишет только VBA. Пока ключ есть, PQ удаляет только свёрнутое. Вернуть прежнее «просто удалять» — удалить строку ключа |
| `DATA/KEEP_WEEKS` | 52 | как раньше; 0 — ни ретеншна, ни свёртки |

Ручной запуск: макрос `modRollup.RollupNow` (строки уйдут при следующей загрузке).

## 3. Потребитель в отчёте

`{{BLOCK_HISTORY_DENT}}` / `{{BLOCK_HISTORY_DGM}}` (слайды 2 и 3, `modContentDisc.BuildHistory`):
«% планшета» по месяцам за всю глубину (до 24 месяцев) — архив + живые события, график
столбики/линия и таблица с дельтой к предыдущему месяцу. Архив пуст — ряд строится по
живым данным, об этом написано под таблицей.

## 4. Изменённые файлы

- `src/vba/modRollup.bas` — новый (Core);
- `src/powerquery/qRollupUntil.pq` — новый, «только подключение»;
- `src/powerquery/Query-ImportJSON.pq` v9.0 — `EffCutoff = min(Cutoff, qRollupUntil)`;
- `src/vba/modMain.bas` v9.0 — вызов свёртки перед Refresh;
- `src/vba/modContentDisc.bas` v1.7 — `BuildHistory`, месячные счётчики в `EnsureDisc`.

`install.ps1` ставит новые `.bas`/`.pq` сам (перебирает папки целиком); `qRollupUntil`
добавляется как запрос без загрузки на лист.

## 5. Что проверить на первом прогоне

1. `install\install.ps1 -Target build -InstallOnly`, `tools/compile_check.ps1` → COMPILE_OK.
2. На копии рабочей книги поставить `DATA/KEEP_WEEKS = 8`, «Загрузить» — в журнале веха
   «Свёрнуто событий: N -> строк архива: M»; на листе `tbARCHIVE` строки; в `Variable`
   появился `DATA/ROLLUP_UNTIL`; в `tbDATA` строк стало меньше ровно на свёрнутые.
3. Сверка: `SUM(tbARCHIVE[events])` + строк `tbDATA` = строк до загрузки + новых из файла.
4. Отчёт: блок истории на слайдах 2–3 показывает месяцы старше окна.
5. Вернуть `KEEP_WEEKS = 52`.
