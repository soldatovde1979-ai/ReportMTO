**Версия:** 1.0 от 29.09.2026. **Ветка:** `ccr-31ac397a-i9sdbi`.
**Поручение владельца (29.09.2026):**
1. доработать всё, что можно; открытые вопросы закрыть своими ответами по целесообразности;
2. доработать движок сворачивания данных — без вопросов, решение придумать самому;

4. в отчёте непонятно, за какой период он — сделать обязательно; указать, какую пользу несёт

## 1. Что сделано — по пунктам поручения

### 1.1 Движок свёртки данных (п. 2)

Постановка и устройство — [`tz_svertka_istorii_v1.0.md`](tz_svertka_istorii_v1.0.md).
Коротко: перед каждой загрузкой старые события (старше окна `DATA/KEEP_WEEKS`) сворачиваются
в таблицу `tbARCHIVE` — неделя × аналитики × счётчики; ретеншн удаляет только то, что уже
в архиве (водяной знак `DATA/ROLLUP_UNTIL`). История больше не теряется, таблица не растёт
линейно. Потребитель — новый блок «История дисциплины по месяцам» на слайдах 2 и 3.

### 1.2 Период (п. 4)

Период теперь виден **всегда**, а не только в шапке:

- закреплённая строка «Период отчёта» над слайдами — отчётная неделя с датами, «с начала
  года» с датами, дата обрыва выгрузки; не уходит при прокрутке;
- в шапке **каждого** слайда — плашка «неделя 2026-38 · 15.09–21.09.2026»;
- вкладка браузера — «Отчёт МТО · неделя 2026-38 (15.09–21.09.2026)». **Найден дефект:**
  `<title>` шаблона был зашит как «2026-13» и показывал чужую неделю при любом отчёте;
- над каждым блоком, как и раньше, — подпись периода сбора с конкретными датами;
- `REPORT/WEEK` теперь задаёт неделю **всему** отчёту (раньше — только промпту ИИ, и выводы
  говорили об одной неделе, а таблицы — о другой).

### 1.3 Польза каждого слайда и блока (п. 4)

У каждого слайда — строка «Вопрос слайда», у каждого блока — строка «Зачем»: какую проблему
подсвечивает или какое решение помогает принять. Полный перечень — раздел 4 этого документа.

### 1.4 Мнение по каждому слайду (п. 7)

- Промпт ИИ переписан: по каждому слайду три пункта — наблюдение с числом, что это значит,
  конкретное действие; ИИ получает `auto_signals` — сигналы правил с готовыми числами.
- **Если ИИ недоступен** (а по журналу это частый случай), вместо заглушки «Внешний ИИ
  недоступен» по каждому слайду выводится **автовывод по правилам** из чисел того же слайда
  с метками «проблема / внимание / хорошо». Источник подписан под списком.
- Диагностика: `GenerateReport` проверяет ошибку после каждого шага (ENDPOINT → ключ → промпт)
  и пишет в журнал номер шага; при пустом ключе запрос не уходит вовсе (задача 9.5).

### 1.5 «Вау-эффект» (п. 6)

- **«Главное за неделю»** — панель над слайдами: до шести самых острых сигналов со всех
  восьми слайдов, красные сверху; клик по пункту открывает нужный слайд.
- **Презентационный режим** — кнопка «Презентация» или клавиша **P**: полный экран, без шапки,
  крупнее, листание стрелками / PageUp / PageDown / Home / End, Esc — выход.

- **Анимация чисел** плиток KPI при открытии слайда (отключается системной настройкой
  «уменьшить движение»).
- **Прямая ссылка на слайд** — `Report_….html#s6` открывает слайд 6; счётчик «6 / 8» и полоса
  прогресса.
- Кнопка «Печать / PDF».
- **История дисциплины за всю глубину** — помесячный тренд % планшета (с архивом свёртки).

## 3. Риски

- **Компиляция.** Новые функции: `modRollup` целиком, `BuildHistory`, `AutoLines` (две
  реализации), `ExecSummary`, `AutoList`, `PeriodChip`, `BuildPhasesByType`, переписанные
  `RetPairs`, `EnsureRet`, `RetArmCollect`, `BuildRetKpi`. Типы, свойства объектов и позднее
  связывание линтер не проверяет.
- **Числа возвратов сдвинутся** — не из-за ошибки: сменились база («Внеплановый ремонт»
  вместо «Отказ»), точка отсчёта (последняя подпись), отнесение пары (к возвратному наряду)
  и знаменатель (с начала года). Сверять с `tools/check_returns_v1.py`, а не с прошлым отчётом.
- **«По группе дефекта» — 44,5 % за 30 суток** на свежей выгрузке. Группа слишком широкая
  («Целостность и внешний вид» и т. п.); главным показателем стоит считать «по подкатегории».
- **Свёртка на рабочей книге.** Первый запуск с `KEEP_WEEKS = 52` на данных за 2 месяца ничего
  не свернёт — это нормально. Проверку делать на копии с `KEEP_WEEKS = 8` (см. постановку §5).
- **Старые строки `tbDATA` хранят `yearWeek` по прежней формуле** до пересборки; после установки
  рекомендуется «Загрузить пакет» (полная пересборка).
- **Ширина таблиц** разрезов возвратов в две колонки (7 колонок в половине ширины) — в `.scroll`,
  но на проекторе проверить глазами.
- `OpenEdgeMonth` / `OpenEdgeWeek` стали невызываемыми (отнесение к возвратному наряду снимает
  «незакрытое окно» у помесячных блоков). Не удалены — по правилу проекта.

## 4. Зачем каждый слайд и блок

Те же тексты стоят в отчёте строкой «Зачем» над каждым блоком.

### Слайд 1 · Обзор недели

**Вопрос слайда:** Что произошло с ремзоной за неделю: поток нарядов, что застряло и где потерян учёт.

| Блок | Какую пользу несёт / что подсвечивает |
|---|---|
| `{{KPI_OVERVIEW}}` | Пульс недели одним взглядом: сколько нарядов пришло и ушло, и растёт ли то, что висит. «Висит» растёт быстрее «открыто» — ремзона не успевает, это первый сигнал к разбору. |
| `{{BLOCK_ZNTYPE_FLOW_HANG}}` | Показывает, какой вид воздействия застревает: сверху — вид с наибольшей долей висящих нарядов. Отвечает, куда направить ресурс ремзоны в первую очередь. |
| `{{BLOCK_HANG_STATUS_SPECIAL}}` | Подсвечивает «мёртвые» наряды — отменённые с перепланированием и ждущие ТМЦ. Их никто не двигает; растущий хвост — задача снабжению и планированию, а не ремзоне. |
| `{{BLOCK_HANG_STATUS}}` | Где именно стоят незакрытые наряды на конец недели. Большая доля «Работы завершены» / «Готов к выбытию» — ремонт сделан, но наряд не закрыт: проблема учёта, а не ремонта. |
| `{{BLOCK_NOZONE_ZNTYPE}}` | Наряды без ремзоны (пустой пост) по виду воздействия: такие наряды выпадают из всех показателей постов. Показывает, в каком виде работ пост забывают указывать. |
| `{{BLOCK_NOZONE_STATUS}}` | Те же наряды без ремзоны по статусу: если они уже закрыты — пост потерян навсегда, если в работе — ещё можно исправить в 1С. |
| `{{BLOCK_NOPOST_WEEKLY}}` | Динамика доли нарядов без поста: растёт — качество учёта падает и отчёт по ремзонам всё менее достоверен. |
| Мнение по слайду | Три пункта: наблюдение с числом, что это значит, что делать. Пишет внешний ИИ; если он недоступен — правила по числам этого же слайда (источник подписан). |

|---|---|
| `{{BLOCK_WEEKS_DENT}}` | Главный показатель дисциплины ДЭНТ по неделям и ремзонам: где планшет прижился, а где откатились на ПК. Красные ячейки — адрес для разговора с руководителем ремзоны. |

| `{{BLOCK_HISTORY_DENT}}` | Длинный тренд дисциплины ДЭНТ по месяцам, за всю историю (с учётом свёрнутого архива). Отвечает на вопрос «мы растём или это колебание недели». |
