# Сборка ReportMTO.xlsm — постревью-версия (Sprint 1+2)

## Что в этом пакете

- `tools_Build-ReportMTO.ps1` — сборочный скрипт, с двумя точечными правками:
  1. `$AnsiCodePage` берётся из `(Get-Culture)`, а не хардкодится (next-steps.md, Приоритет 2).
  2. `try` вокруг `.OLEDBConnection` — не-OLEDB подключение больше не роняет цикл переименования.
  3. **Новое:** `Add-QueryIfMissing` теперь **обновляет** Formula существующего PQ-запроса,
     если текст файла отличается от того, что уже в книге — раньше существующий запрос
     молча пропускался, а постревью-версия меняет сам контракт `fnNormalizeFields`
     (`(row)→record` на `(table)→table`) и `fnUpsert`/`Query-ImportJSON`. Без этой правки
     повторный запуск скрипта оставил бы в книге старый M-код против новых VBA-модулей.
     Исключение — `prmSourcePath`: это не код, а рабочее состояние (путь к JSON, который вы,
     возможно, уже выбирали через «Загрузить»), он не перезаписывается.
- `src/vba/*.bas` — 9 модулей, постревью-версия.
- `src/powerquery/*.pq` — 5 запросов, постревью-версия.
- `tmp_index.html` — полноценный HTML-шаблон (было: фрагмент).

## Куда положить

```
ВашаПапкаПроекта\
├── build\
│   └── ReportMTO.xlsm          ← книга (скрипт продолжит сборку в нём)
├── tmp_index.html               ← из этого пакета, заменить
├── tools_Build-ReportMTO.ps1    ← из этого пакета, заменить
└── src\
    ├── vba\                     ← 9 файлов из этого пакета
    └── powerquery\               ← 5 файлов из этого пакета
```

Раз `build\ReportMTO.xlsm` уже существует — скрипт откроет **его** (режим «продолжить»), не заготовку
`ReportMTO_starter.xlsx`. Листы Main/Variable/Logs/tbDATA и кнопки останутся как есть.

## Запуск

```powershell
.\tools_Build-ReportMTO.ps1 -ProjectRoot "C:\путь\к\ВашаПапкаПроекта"
```

Перед запуском убедитесь (см. `.NOTES` в самом скрипте):
- Excel → Параметры → Центр управления безопасностью → Параметры макросов →
  «Доверять доступ к объектной модели проектов VBA» — включено.
- Все процессы `EXCEL.EXE` закрыты перед запуском (Диспетчер задач), если только что
  меняли эту настройку.

## Что скрипт сделает

1. Откроет существующий `build\ReportMTO.xlsm`.
2. Удалит и переимпортирует все 9 `.bas`-модулей (полная замена — это ожидаемо и правильно
   для постревью-версии, все они изменились).
3. Обновит 4 функции + `Query-ImportJSON` (если текст изменился — а он изменился у всех пяти).
   `prmSourcePath` не тронет.
4. Шаг 4 (Load To Table) пропустит, если `tbDATA` уже загружена — а она уже загружена в вашем
   файле, так что этот экспериментальный шаг, скорее всего, даже не будет пытаться выполниться.
5. Сохранит книгу.

## После сборки — обязательно вручную

1. **Debug → Compile VBAProject** (Alt+F11 → Debug → Compile). Это первое реальное испытание
   новых сигнатур `modAggregate` — раньше не компилировалось ни разу.
   Вероятные точки сюрпризов:
   - любой вызов агрегации теперь требует активного снимка (`modAggregate.BeginSnapshot`) —
     если где-то в книге остался старый вызов в обход `modContentMTO`, здесь всплывёт;
   - `BuildPlaceholders` теперь принимает 3 параметра, а не 0.
2. Добавить ключ `REPORT/MIN_RECORDS = 5` на лист `Variable` (новый ключ, без него код
   применит значение по умолчанию, но лучше, чтобы был виден).
3. Открыть `Query-ImportJSON` в редакторе Power Query (Данные → Запросы и подключения →
   правой кнопкой → Изменить) — визуально проверить, что M-код открывается без ошибок
   синтаксиса. Статически он не прогонялся ни разу.
4. Прогнать `modMain.DebugGenerateOffline` (можно через Alt+F8 → выбрать макрос → Run) —
   это сборка отчёта с заглушками ИИ, без HTTP-вызова и без реальных данных. Проверяет
   весь путь Блоков 1–9 → HTML на текущих данных в `tbDATA`.
5. Если шаг 4 прошёл — сначала на тестовом/обезличенном JSON, потом на реальных данных
   прогнать полный `GenerateReport` с живым API-ключом DeepSeek.

Если что-то упадёт на компиляции или на `DebugGenerateOffline` — пришлите точный текст
ошибки и номер строки/модуля, будем разбирать по месту.
