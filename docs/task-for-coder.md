# Задача для кодера: доработка ReportMTO по документу «Презентация и блоки данных» v1.1

> Целевые требования и наметки — [`docs/Презентация и блоки данных.md`](docs/Презентация и блоки данных.md)
> (разделы 2–4: блоки и презентация; раздел 5: сводная таблица наметок, 13 пунктов).
> Платформа и контракты — [`docs/spec.md`](docs/spec.md:1), [`docs/content-spec.md`](docs/content-spec.md:1).
> Правило проекта: при противоречии документов и кода верен код; Core не менять ради специфики МТО.

## 0. Точки приложения

- [`src/vba/modContentMTO.bas`](src/vba/modContentMTO.bas:1) — все функции `Build*`, `BuildPrompt`, `ParseAIResponse`, `BuildPlaceholders`.
- [`src/vba/modMain.bas`](src/vba/modMain.bas:1) — `GetVariable`/`GetVariableDef` (чтение новых ключей).
- [`src/vba/modHTMLEngine.bas`](src/vba/modHTMLEngine.bas:1) — `HtmlEscape`, `RenderTemplate`, `SaveHTMLFile` (не менять).
- [`tmp_index.html`](tmp_index.html:1) — шаблон (пересборка под 7 слайдов).
- Лист `Variable` — новые ключи.

## 1. Новые ключи Variable (все с дефолтами)

| Ключ | Значение по умолчанию | Назначение |
|---|---|---|
| `REPORT/WEEK` | пусто/`0` = авто: неделя последнего ЗН − 1 | отчётная неделя (ПН); явное число = указанная неделя |
| `REPORT/MIN_POST_RECORDS` | `10` | порог «мало данных» в оценке Блока 2 |
| `REPORT/SLIDE_ZONES` | `СТК+ПРК` | набор ремзон второго экземпляра Блока 1 на слайдах дирекций; пусто = не выводить |
| `NormaForPlanshet` | `90` | порог «норма» Блока 2 |
| `ProvalForPlanshet` | `50` | порог «провал» Блока 2 |

Существующие ключи (`REPORT/WEEKS_WINDOW`, `REPORT/TOPN`, `REPORT/MIN_RECORDS`, `REPORT/SYNC_THRESHOLD_MIN`) продолжают использоваться.

## 2. Состав работ (порядок по приоритетам; нумерация — по разделу 5 целевого документа)

1. **П.2 — ключи `REPORT/WEEK` и прочие:** чтение через `GetVariableDef`; расчёт ПН; применение в Дашборде, Блоке 2, Блоке 6.
2. **П.4 — Дашборд 1:** переключатель периодов («с начала года» / «последняя неделя» / «предыдущая неделя»);
   показатели: «создали» (Distinct `number` по `date`), «закрыли» (Distinct `number` со статусом «Готов к выбытию» по `status_date`), «% планшет», «без поста ремзоны» (Distinct `number` с пустым `postN`), «медиана» (медиана `deltaHours` по ЗН, вывод «чч:мм»); два экземпляра на Слайде 1 (год и ПН).
3. **П.3 — Блок 1:** параметры «Дирекция» и «Ремзоны»; окно 8 недель от отчётной недели.
4. **П.5 — Блок 2:** колонки Пост | Нарядов (`Distinct number`) | Событий (`Count`) | % планшета | ДГМ | ДЭНТ | Оценка.
   Оценка: «мало данных» (нарядов < `MIN_POST_RECORDS`) → «норма» (≥ `NormaForPlanshet`) → «провал» (< `ProvalForPlanshet`) → иначе без текстовой оценки.
5. **П.6 — Блок 6:** понедельная раскладка ПН-3…ПН (группы колонок из раздела 3.6.1 целевого документа) по сотрудникам **и по подразделениям** (`emp_dep`); сортировка по «% планшет» ПН по убыванию; рейтинг топ/антитоп — **за отчётную неделю** (`REPORT/WEEK`), порог `MIN_RECORDS` сохраняется.
6. **П.7 — Блок 7:** добавить «10 аномалий» — топ-10 нарядов с максимальным расхождением `status_date` «Готов к выбытию» между ДГМ и ДЭНТ (выводить: номер ЗН, пост, даты-время обеих дирекций, разница «чч:мм»).
7. **П.8 — Блок 9а:** строки — вид ремонта (`zn_type`, срез `defekt_type`), колонки ДГМ / ДЭНТ, значение — «% планшет».
8. **П.9 — Презентация:** пересборка [`tmp_index.html`](tmp_index.html:1) под 7 слайдов (Обзор; ДЭНТ; ДГМ; Синхронность; Дефекты и рейтинг; Динамика по дирекциям; Динамика по постам). Плейсхолдеры: `{{DASH_1_YTD}}`, `{{DASH_1_PREV}}`, `{{BLOCK_2_PREV}}`, `{{BLOCK_2_CHART}}`, `{{BLOCK_1_DENT_ALL}}`, `{{BLOCK_1_DENT_ZONES}}`, `{{BLOCK_1_DGM_ALL}}`, `{{BLOCK_1_DGM_ZONES}}`, `{{BLOCK_6_DENT}}`, `{{BLOCK_6_DGM}}`, `{{BLOCK_7_TABLE}}`, `{{BLOCK_8_TABLE}}`, `{{BLOCK_9_TABLE}}`, `{{BLOCK_9A_TABLE}}`, `{{BLOCK_6_RATING}}`, `{{BLOCK_4_TABLE}}`, `{{BLOCK_5_TABLE}}` + `{{AI_INSIGHT_SLIDE_N}}` (N=1…7).
9. **П.9 — ИИ-выводы:** ключи `slide1…slide7_conclusions` в [`BuildPrompt()`](src/vba/modContentMTO.bas:175) и [`ParseAIResponse()`](src/vba/modContentMTO.bas:297). **Псевдонимизация:** маппинг `employee` → «Сотрудник N» (стабильная сортировка по алфавиту, живёт один прогон); в промпт — только номера и агрегаты по людям (например `block6_people`: номер, % планшет ПН и ПН-1, число подписаний); при вставке в HTML — обратная замена номеров на ФИО. Таблица соответствия наружу не уходит.
10. **П.1 — Расшифровка/гиперссылки:** встроенный в HTML дамп строк `tbDATA` **с ФИО** (решение заказчика) за предыдущую и текущую недели; поля: `number`, `date`, `ready_for`, `direction`, `status_date`, `arm`, `post`, `employee`; клик по цифре блока раскрывает относящиеся строки; визуально цифры — как текст.
11. **П.10 — График:** столбики по Блоку 2 (посты × «% планшет» или нарядов) — офлайн, инлайн-SVG/JS, без внешних библиотек.
12. **П.13 — Описания расчёта:** под каждым блоком на слайде — краткая подпись «как считается» (фильтр/формула), тексты — из разделов 2–3 целевого документа.
13. **П.11 — Терминология:** все сравнения статусов — через `NormStatus` («ё»→«е»), «Готов к приёмке»/«Готов к выбытию».

## 3. Допущения (не блокируют работу; помечать `TODO` в коде)

- «Последняя неделя» = максимальный `yearWeek`, присутствующий в данных; «с начала года» = записи текущего года (`year_status`), создание — по `date`.
- Медиана считается по ЗН, у которых есть обе статусные записи в дирекции; вывод «чч:мм» с округлением до минут.
- «Серая зона» Блока 2 (50 ≤ % < 90) — без текстовой оценки, без подсветки.
- Ось подблока 9а — `zn_type`; срез `defekt_type` — второй уровень, если заполнен.
- Дамп расшифровки сериализуется в JSON внутри отчёта один раз на прогон (снимок `modAggregate`).
- Псевдонимы «Сотрудник N» нумеруются по алфавиту ФИО; замена выполняется только в тексте ИИ-выводов.

## 4. Обязательные правила

- Правки только в `modContentMTO.bas`, `tmp_index.html`, значения листа `Variable`; Core-модули не менять.
- Базовый фильтр всех блоков: `in_bounds = ИСТИНА`, `arm ∈ {ПК, ПЛАНШЕТ}` через `FBase`/`FArm`/`FTablet` («НЕ ПОДПИСАНО» исключается).
- Все значения, попадающие в HTML (данные 1С и текст ИИ), — через `modHTMLEngine.HtmlEscape`; шаблон и результат — UTF-8.
- В промпт — только белый список полей; `employee` — только псевдонимами; `defect_desc` не передаётся никогда.
- VBA должен компилироваться (Debug → Compile); сортировки — существующим `SortDictionaryKeysByValue`/`SortKeys`; без правки `modAggregate.bas`.

## 5. Критерии приёмки

- Чек-лист [`content-spec.md` §11](docs/content-spec.md:399) выполняется полностью.
- Новые: ключи `Variable` читаются с дефолтами; отчёт собирается на 7 слайдов; выводы `slide1…slide7` реально попадают на слайды (при успешном ответе DeepSeek); псевдонимы заменяются на ФИО; клик по цифре раскрывает строки за две недели (с ФИО); рейтинг — за отчётную неделю; медиана — «чч:мм»; в Блоке 7 — топ-10 аномалий; график по Блоку 2 рендерится офлайн; у каждого блока — подпись с описанием расчёта.
- Проверить прогоном на тестовом JSON (в т.ч. граничные случаи: пустой `post`, >2 статусных записей, ЗН только в одной дирекции).
