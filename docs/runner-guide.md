# Помощник ReportMTO — что это и как им пользоваться

> Версия 2.0 от 12.09.2026. Переписан под две очереди: длинную и быструю.
> Версия 1.2 от 11.09.2026. Первая редакция (одна очередь).

## Зачем он нужен

Claude правит файлы проекта напрямую, но **запускать что-либо на вашей машине не
может**: PowerShell и IDE ему выдаются только в режиме «вижу и кликаю», без ввода
с клавиатуры. Помощник закрывает эту дыру: Claude кладёт **задание** в папку,
задача планировщика его выполняет, ответ пишется в **лог**, Claude лог читает.

Произвольные команды не выполняются — только имена задач из закрытого списка.

## Две очереди и почему их две

| | Длинная | Быстрая |
|---|---|---|
| Скрипт | `tools\jobs\runner.ps1` | `tools\jobs\runner-fast.ps1` |
| Задача планировщика | `ReportMTO-Runner`, раз в 2 мин | `ReportMTO-Runner-Fast`, раз в 1 мин |
| Папка заданий | `tools\jobs\queue` | `tools\jobs\fast-queue` |
| Папка ответов | `tools\jobs\out` | `tools\jobs\fast-out` |
| Для чего | релиз, отчёт, загрузка, пересборка, git | состояние, остановка, диагностика |

Планировщик Windows **не запускает вторую копию одной задачи**, пока работает
первая. 11.09.2026 загрузка данных шла 5 часов, и всё это время помощник не мог
выполнить ничего — даже «остановись». Быстрая очередь — отдельная задача
планировщика, поэтому она жива всегда.

## Что он умеет

### Длинная очередь

| Задача | Что делает | Аргументы |
|---|---|---|
| `release` | установка модулей и запросов, компиляция, версия, миграции, CHANGELOG | `-DryRun`, `-Bump patch\|minor\|major`, `-Force`, `-SkipCompile` |
| `report` | открыть книгу, собрать отчёт, закрыть | нет |
| `load` | загрузка `data\*.json` по одному файлу, живой лог | подстрока имени файла |
| `rebuild` | **полная пересборка**: копия книги → очистка `tbDATA` → один проход по папке | нет |
| `compile` | принудительная компиляция VBA | нет |
| `gitsync` | `fetch` → `merge` → `push` | нет |
| `closeexcel` | аккуратно закрыть книгу и Excel через COM | нет |
| `aikey` | перенести ключ ИИ в `%APPDATA%\ReportMTO` | нет |
| `installfast` | зарегистрировать быструю очередь | нет |
| `diag` | сбор фактов: RDP, окружение, git, сеансы | `rdp`, `env`, `git`, `session`, `all` |

### Быстрая очередь

| Задача | Что делает | Аргументы |
|---|---|---|
| `ping` | жив ли помощник, занята ли книга, хвост живого лога | нет |
| `stop` | флаг мягкой остановки — длинная задача остановится между файлами | нет |
| `kill` | аварийно снять Excel и зависший экземпляр длинной очереди | `confirm` |
| `diag` | то же, что в длинной | `rdp`, `env`, `git`, `session`, `all` |
| `screenshot` | снимок рабочего стола в `out\screen.png` | нет |
| `wakescreen` | разбудить дисплей сдвигом курсора | нет |

## Как это выглядит

- задание — файл `queue\<номер>_<имя>.job`, внутри одна строка: `release -DryRun`;
- ответ — `out\<то же имя>.log`;
- журнал очереди — `state\runner.log` и `state\runner-fast.log`;
- пульс — `state\heartbeat.txt` (длинная) и `state\heartbeat-fast.txt` (быстрая).

**Пульс длинной очереди замирает на время работы** — это нормально, так устроен
планировщик. Честный признак «помощник жив» — пульс быстрой очереди.

Долгие задачи пишут **живые логи**, они обновляются по ходу:
`out\load-live.log` и `out\rebuild-live.log`. Обычный лог задания появляется
только после её завершения, поэтому для долгих задач смотрите живой.

## Установка и снятие

Ставится один раз двойным щелчком по **`ЗАПУСТИТЬ-ПОМОЩНИКА.bat`** в корне
проекта. Быструю очередь после этого Claude ставит сам задачей `installfast`.

Снять: `tools\jobs\remove-runner.bat` (длинная) и
`schtasks /Delete /TN "ReportMTO-Runner-Fast" /F` (быстрая).

## Границы безопасности

- выполняются только имена задач из списков выше, аргументы проверяются
  регулярным выражением; произвольные команды невозможны;
- задание уносится из очереди до выполнения, а при существующем логе —
  пропускается: разрушающая задача не может выполниться дважды;
- без повышения прав, всё от вашей учётной записи;
- `rebuild` делает копию книги в `bak\` **до** очистки и не сохраняет результат,
  если строк оказалось меньше тысячи;
- `kill` требует явного аргумента `confirm`.

## Известные ограничения

1. Задержка до 2 минут (длинная) и до минуты (быстрая) — задания не мгновенные.
2. Пока идёт длинная задача, длинная очередь стоит целиком. Быстрая — работает.
3. Прервать уже идущее обновление Power Query нельзя иначе как снятием Excel
   (`kill confirm`): обновление выполняется внутри Excel и не прерывается.
4. Папка проекта синхронизируется облаком. 12.09.2026 из-за этого файлы заданий
   один раз остались в очереди после выполнения — отсюда защита по логу.

## Если помощник не отвечает

1. `state\heartbeat-fast.txt` — свежая ли отметка. Нет → быстрая задача снята
   или не установлена: `schtasks /Query /TN ReportMTO-Runner-Fast`.
2. `state\runner-fast.log` и `state\runner.log` — что делал последним.
3. Задание осталось в `queue\`, лога нет → до него не дошли; лог есть, а в
   `state\processed\` файла нет → сработала защита от повтора.
4. Длинная очередь стоит часами → положите в `fast-queue` задание `ping`, потом
   `kill confirm`.
