# Помощник ReportMTO (tools\jobs) — как это работает

> Версия 1.1 от 11.09.2026. Установщик вынесен в корень под именем
> ЗАПУСТИТЬ-ПОМОЩНИКА.cmd и сам проверяет результат; снятие переименовано и убрано
> в tools\jobs, чтобы их нельзя было перепутать.
> Версия 1.0 от 11.09.2026.

## Зачем

Чтобы задачи на этой машине выполнялись без человека: Claude кладёт задание в
очередь, помощник его выполняет, ответ пишется в лог, Claude лог читает.

## Установка — один раз

Двойной щелчок по **`ЗАПУСТИТЬ-ПОМОЩНИКА.cmd`** в корне проекта. Права
администратора не нужны. Он ставит задачу планировщика **ReportMTO-Runner**
(раз в 2 минуты проверяет очередь), запускает её сразу и показывает результат
проверки — если что-то не так, окно об этом скажет прямо.

Снять: `tools\jobs\remove-runner.cmd`. Он намеренно лежит не рядом с запуском и
называется иначе: 11.09.2026 два похожих файла в одной папке уже привели к тому,
что вместо установки сняли несуществующую задачу.

## Что можно поручить

Список закрыт и зашит в `runner.ps1`. Произвольные команды не выполняются —
в задании может стоять только имя из этой таблицы.

| Задача | Что делает | Ключи |
|---|---|---|
| `gitsync` | `fetch` → `merge origin/main` → `push` | нет |
| `release` | `install\release.ps1` — установка, компиляция, версия, миграции | `-DryRun`, `-Bump patch\|minor\|major`, `-Force`, `-SkipCompile` |
| `compile` | `tools\compile_check.ps1` на рабочей книге | нет |
| `report` | открывает книгу, строит отчёт, закрывает без сохранения | нет |
| `diag` | сбор фактов: RDP, окружение, git. Только чтение | `rdp`, `env`, `git`, `all` |

## Как это выглядит

- задание: файл `tools\jobs\queue\<номер>_<имя>.job`, внутри одна строка — `release -DryRun`;
- ответ: `tools\jobs\out\<то же имя>.log`;
- журнал помощника: `tools\jobs\state\runner.log`;
- отметка «жив»: `tools\jobs\state\heartbeat.txt` обновляется каждые 2 минуты.

## Границы безопасности

- выполняются только имена задач из списка выше, ключи проверяются построчно;
- задание уносится из очереди **до** выполнения — повторно не сработает;
- без повышения прав, от вашей учётной записи;
- длинные задачи защищены замком `state\runner.lock` — параллельных запусков нет;
  замок старше 90 минут считается зависшим и снимается;
- очередь и логи не версионируются (в `.gitignore`);
- снимается одним файлом, задача планировщика удаляется целиком.

## Если помощник не отвечает

1. `tools\jobs\state\heartbeat.txt` — свежая ли отметка. Старая → задача не работает,
   проверьте `schtasks /Query /TN ReportMTO-Runner`.
2. `tools\jobs\state\runner.log` — что он делал в последний раз.
3. Задание осталось в `queue\` → помощник до него не дошёл; ушло в
   `state\processed\`, а лога нет → упал на исполнении.
