## 1. КРИТИЧНО — устранить до начала работы над блоками

Эти три пункта не являются «доработками» — без них дальнейшая реализация либо не скомпилируется,
либо будет молча терять данные. Делать первыми, отдельным коммитом/этапом.

### 1.1 Конфликт контракта: 7 слайдов vs неизменяемый `modMain.bas`

**Проблема.** `modMain.GenerateReport` (Core, неизменяем) вызывает функции с фиксированной
сигнатурой:

```vba
parsedOK = modContentMTO.ParseAIResponse(responseText, slide3, slide4, slide5)
...
Set placeholders = modContentMTO.BuildPlaceholders(slide3, slide4, slide5)
```

Ровно 3 позиционных `ByRef`-параметра. Требование «ключи `slide1…slide7_conclusions`» напрямую
противоречит этому, если пытаться расширить сигнатуру — компиляция не пройдёт (Core неизменяем),
либо потребуется правка `modMain.bas`, что запрещено.

**Решение.** Сигнатуры `ParseAIResponse` и `BuildPlaceholders` **не меняются**. Все 7 значений
разбираются и хранятся внутри `modContentMTO.bas` в приватном кэше на прогон — по аналогии с
существующим паттерном `mPairs`/`mPairsReady` (`BuildSyncPairs`).

```vba
Private mSlideConclusions(1 To 7) As String
Private mSlideConclusionsReady As Boolean

Public Function ParseAIResponse(responseText As String, ByRef slide3 As String, _
    ByRef slide4 As String, ByRef slide5 As String) As Boolean
    ' ... двухшаговый разбор, как сейчас, но по ключам slide1..slide7_conclusions ...
    ' Заполняет mSlideConclusions(1..7).
    ' slide3/slide4/slide5 заполняются как раньше — ИЗ ТОГО ЖЕ кэша, для обратной
    ' совместимости вызова из modMain (он использует только эти три параметра напрямую).
    slide3 = mSlideConclusions(3)
    slide4 = mSlideConclusions(4)
    slide5 = mSlideConclusions(5)
    mSlideConclusionsReady = True
    ParseAIResponse = ok ' True, если распознаны ВСЕ 7 ключей
End Function

Public Function BuildPlaceholders(aiSlide3 As String, aiSlide4 As String, aiSlide5 As String) As Object
    ' aiSlide3/4/5 — параметры от modMain, используются как раньше (fallback на заглушку,
    ' если ParseAIResponse не вызывался или вернул False для конкретного слайда).
    ' Слайды 1, 2, 6, 7 берутся из mSlideConclusions, если mSlideConclusionsReady = True,
    ' иначе — из константы AI_FALLBACK.
End Function
```

**Правило деградации:** если `mSlideConclusionsReady = False` (ИИ недоступен/`ParseAIResponse`
не вызывался — путь `DebugGenerateOffline`), все 7 плейсхолдеров `{{AI_INSIGHT_SLIDE_N}}`
получают `AI_FALLBACK`, как сейчас для 3.

**Почему это безопасно относительно Core:** `modMain.bas` вызывает функции по тем же именам,
с тем же числом параметров, с той же семантикой — модуль ничего не знает про кэш и про 7 слайдов.

### 1.2 Рассинхрон разделителей `+` / `;` в фильтре ремзон — тихая потеря данных

**Проблема.** `REPORT/SLIDE_ZONES` задаётся как `СТК+ПРК` (разделитель `+`, см. раздел 2).
`modAggregate.RowMatchesFilters` понимает фильтр вида `"postN@=СТК;ПРК"` — разделитель списка
внутри `@=` строго `;` (`Split(val, ";")`, см. `modAggregate.bas`). Если передать
`"postN@=" & GetVariableDef("REPORT/SLIDE_ZONES", "СТК+ПРК")` буквально, фильтр получит
`postN@=СТК+ПРК` — это одно значение `"СТК+ПРК"`, которому не равен ни один `postN`. Результат:
**пустая таблица без единой ошибки** — блок молча покажет «нет данных» вместо реальных строк.

**Решение.** Обязательная функция-конвертер при чтении ключа, до передачи в фильтр:

```vba
' "СТК+ПРК" -> "СТК;ПРК" (формат modAggregate.RowMatchesFilters, разделитель ";")
' Пусто -> пусто (означает "без второго экземпляра Блока 1", raздел 3.2).
Private Function SlideZonesToFilterList(raw As String) As String
    SlideZonesToFilterList = Replace(Trim$(raw), "+", ";")
End Function
```

Использовать **везде**, где `REPORT/SLIDE_ZONES` попадает в фильтр `postN@=...`. Юнит-проверка
приёмки: при значении по умолчанию `СТК+ПРК` второй экземпляр Блока 1 должен показывать
ненулевые данные хотя бы по одной из двух зон (если они есть в тестовом наборе).

### 1.3 Риск границы года в новых оконных расчётах

**Проблема.** Существующий код (`BuildBlock3KPI`) уже один раз наступал на эти грабли и обходит
их через `yearWeek` (см. комментарии P1-4 в `modContentMTO.bas`) — окно недель берётся как
**последние N значений `yearWeek`, реально присутствующих в данных**, а не арифметикой
`currentWeek − N + 1`. Новые блоки (Блок 1 — окно 8 недель; Блок 6 понедельный — ПН-3…ПН)
обязаны использовать **тот же паттерн**, а не собственную арифметику по номеру недели.

**Решение — переиспользовать существующий фрагмент как есть:**

```vba
' Общий приём (см. BuildBlock3KPI): weeks = SortKeys(..., True); брать
' weeks(UBound-N+1 .. UBound) — то есть N последних РЕАЛЬНО ПРИСУТСТВУЮЩИХ значений yearWeek,
' а не currentWeek-N+1. Арифметика по номеру недели ломается на границе года
' (43/2025 и 43/2026 — разные yearWeek, но одна и та же арифметика "−N" даёт коллизию).
```

Это правило применяется в разделах 3.2 (Блок 1, окно 8 недель) и 3.6 (Блок 6, ПН-3…ПН).

Все — через `GetVariableDef`, обязательны дефолты, чтение из `modMain.bas` не меняется

### 2.1 Расчёт `REPORT/WEEK` (авто-режим)

```
weekKey = GetVariableDef("REPORT/WEEK", "")
Если weekKey пусто или "0":
    ПН = второе с конца значение из отсортированных РЕАЛЬНО ПРИСУТСТВУЮЩИХ yearWeek
         (т.е. weeks(UBound-1), где weeks = SortKeys(distinctByWeek, True) —
          тот же массив, что уже строится в BuildBlock3KPI)
Иначе:
    ПН = явно указанный номер недели, ИНТЕРПРЕТИРУЕТСЯ как компонент недели без года —
         преобразуется в yearWeek через year_status последней присутствующей в данных записи
         этого номера недели (искать среди существующих yearWeek с week-частью = weekKey;
         если несколько лет содержат такую неделю — взять более позднюю; если ни одной — Блок 2/6
         за эту неделю пуст, вывести "нет данных за указанную неделю" вместо ошибки).
ПН-1, ПН-2, ПН-3 = три предыдущих значения из того же отсортированного массива weeks
         (не арифметика "−1/−2/−3" от номера недели — см. 1.3).
```

**Важно:** если данных меньше 4 недель (`UBound(weeks) - LBound(weeks) < 3`), понедельная
раскладка Блока 6 (раздел 3.6) выводит только доступные недели с пометкой «данных за
предыдущие недели нет», не падает с ошибкой индекса массива.

## 3. Блоки — детальная спецификация

### 3.1 Дашборд 1 (Блок 3, `BuildBlock3KPI`)

**Параметры:** период — с начала года / последняя неделя / предыдущая неделя (ПН,
`REPORT/WEEK`). На Слайде 1 — два независимых вызова функции с разными периодами.

**Показатели (все 6, включая уже реализованные 2):**

| Показатель | Формула | Фильтр |
|---|---|---|
| Период | подпись | — |
| Создали ЗН | `Distinct number`, `date` в периоде | без `FBase` — по всей истории строк, включая «НЕ ПОДПИСАНО» (создание ЗН не зависит от статуса подписи) |
| Закрыли ЗН | `Distinct number`, `ready_for = "Готов к выбытию"` (через `NormStatus`), `status_date` в периоде | `FBase()` |
| % планшет | `tablet/total` за период | `FArm()`/`FTablet()` |
| Без поста ремзоны | `Distinct number`, `postN = ""`, за период | `FBase()` |
| Медиана | медиана `deltaHours` по `number` (одно значение на ЗН — берётся из строки «Готов к выбытию»), формат «чч:мм» | `FBase()`, только строки с непустым `deltaHours` |

**Формат медианы «чч:мм»:**
```vba
Private Function HoursToHHMM(h As Double) As String
    Dim totalMin As Long: totalMin = CLng(Round(h * 60))
    HoursToHHMM = CStr(totalMin \ 60) & ":" & Format(totalMin Mod 60, "00")
End Function
```

**Медиана через `modAggregate` — ограничение и обход.** `modAggregate` не имеет функции медианы.
Не расширять `modAggregate.bas` (Core). Решение: собрать массив `deltaHours` вручную прямым
проходом по снимку (`modAggregate.RowCount`/`CellRaw`/`CellText`, тот же паттерн, что уже
использует `BuildSyncPairs`), отсортировать пузырьком (массивы блоков — сотни значений, `O(n²)`
приемлемо, как и в `SortDictionaryKeysByValue`), взять центральный элемент(ы).

```vba
Private Function MedianDeltaHours(filters As Variant) As Double
    Dim vals() As Double, n As Long
    Dim r As Long, cnt As Long
    cnt = modAggregate.RowCount()
    ReDim vals(0 To cnt - 1)
    n = 0
    For r = 1 To cnt
        If RowMatchesBaseAndPeriod(r, filters) Then ' проверка in_bounds/arm/period/deltaHours<>""
            Dim dh As Variant: dh = modAggregate.CellRaw(r, "deltaHours")
            If IsNumeric(dh) And Not IsEmpty(dh) Then
                vals(n) = CDbl(dh): n = n + 1
            End If
        End If
    Next r
    If n = 0 Then MedianDeltaHours = 0: Exit Function
    ReDim Preserve vals(0 To n - 1)
    ' сортировка пузырьком по возрастанию
    Dim a As Long, b As Long
    For a = 0 To n - 2
        For b = 0 To n - 2 - a
            If vals(b) > vals(b + 1) Then
                Dim t As Double: t = vals(b): vals(b) = vals(b + 1): vals(b + 1) = t
            End If
        Next b
    Next a
    If n Mod 2 = 1 Then
        MedianDeltaHours = vals(n \ 2)
    Else
        MedianDeltaHours = (vals(n \ 2 - 1) + vals(n \ 2)) / 2
    End If
End Function
```

**Приёмка:** оба экземпляра Дашборда (год/ПН) выводят все 6 показателей; медиана в формате
«5:20», а не «5,33» или «5.33333».

### 3.2 Блок 1 (`BuildBlock1Table`) — параметризация + окно 8 недель

**Новая сигнатура (внутренняя, вызывается 4 раза для Слайдов 2–3):**

```vba
Private Function BuildBlock1Table(Optional direction As String = "", Optional zonesCsv As String = "") As String
```

- `direction = ""` → обе дирекции (текущее поведение по умолчанию для Слайда 2, если он
  сохраняется где-то ещё; целевая презентация вызывает с явной дирекцией).
- `direction = "ДГМ"` / `"ДЭНТ"` → фильтр добавляет `"direction=" & direction` к `FArm()`/`FTablet()`.
- `zonesCsv = ""` → без ограничения по постам (весь Блок 1, как сейчас).
- `zonesCsv <> ""` (например результат `SlideZonesToFilterList` из 1.2) → добавляет
  `"postN@=" & zonesCsv` к фильтрам.

**Окно 8 недель:** после построения оси `weeks` (`AxisFromKeys`) обрезать до последних 8
элементов **по факту присутствия в данных** (см. 1.3), а не «неделя ≥ currentWeek−8»:

```vba
Dim weeksWindow As Long: weeksWindow = 8 ' фиксировано docx, не вынесено в Variable — см. допущения
If UBound(weeks) - LBound(weeks) + 1 > weeksWindow Then
    Dim newWeeks() As Variant
    ReDim newWeeks(0 To weeksWindow - 1)
    Dim i As Long
    For i = 0 To weeksWindow - 1
        newWeeks(i) = weeks(UBound(weeks) - weeksWindow + 1 + i)
    Next i
    weeks = newWeeks
End If
```

**4 вызова для презентации** (раздел 4):
- `BuildBlock1Table("ДЭНТ", "")` → `{{BLOCK_1_DENT_ALL}}`
- `BuildBlock1Table("ДЭНТ", SlideZonesToFilterList(...))` → `{{BLOCK_1_DENT_ZONES}}`
- `BuildBlock1Table("ДГМ", "")` → `{{BLOCK_1_DGM_ALL}}`
- `BuildBlock1Table("ДГМ", SlideZonesToFilterList(...))` → `{{BLOCK_1_DGM_ZONES}}`

Если `REPORT/SLIDE_ZONES` пусто — `{{BLOCK_1_*_ZONES}}` заполняется пояснением
«Набор ремзон не задан (Variable/REPORT/SLIDE_ZONES)», не пустой таблицей и не ошибкой.

**Приёмка:** каждый из 4 вызовов показывает не более 8 столбцов недель; при `direction="ДГМ"`
строки ДЭНТ отсутствуют полностью (не нулевые — отсутствуют).

### 3.3 Блок 2 (`BuildBlock2Table`) — расширенные колонки

**Новые колонки:** Пост | Нарядов | Событий | % планшета | ДГМ | ДЭНТ | Оценка.

```vba
Private Function BuildBlock2Table(Optional periodFilters As Variant) As String
    ' periodFilters — доп. фильтр по status_date для "предыдущая неделя" на Слайде 1;
    ' Nothing/не передан -> вся история (для сверки, если понадобится отдельный полный отчёт).

    Dim naryadov As Object   ' Distinct(number) по postN — как сейчас, GroupCountDistinct
    Dim events As Object     ' Count(*) по postN — GroupCount(Array("postN"), filters)
    Dim tabletAll As Object  ' Count(arm=ПЛАНШЕТ) по postN — GroupCount(..., FTablet + postN)
    Dim totalAll As Object   ' Count(arm∈{ПК,ПЛАНШЕТ}) по postN — GroupCount(..., FArm + postN)
    Dim tabletDGM As Object, totalDGM As Object   ' то же + "direction=ДГМ"
    Dim tabletDENT As Object, totalDENT As Object ' то же + "direction=ДЭНТ"

    ' % планшета = tabletAll/totalAll; ДГМ = tabletDGM/totalDGM; ДЭНТ = tabletDENT/totalDENT
    ' Оценка (порядок проверки СТРОГО такой):
    '   1. naryadov(post) < REPORT/MIN_POST_RECORDS  -> "мало данных"
    '   2. pct >= NormaForPlanshet                    -> "норма"
    '   3. pct <  ProvalForPlanshet                    -> "провал"
    '   4. иначе                                       -> "" (серая зона, без оценки, без подсветки)
End Function
```

Пустой `postN` — отдельная строка **«пост не указан»**, участвует в тех же расчётах
(не отбрасывается, не сливается с другими пустыми группами — она и так одна группа по `postN=""`).

**Два вызова:**
- `BuildBlock2Table()` — полная история, для сверки (если нужен где-то ещё).
- `BuildBlock2Table(Array("status_date>=" & <начало ПН>, "status_date<" & <конец ПН>))` →
  `{{BLOCK_2_PREV}}` на Слайде 1.

  > ⚠️ **Ограничение `modAggregate.RowMatchesFilters`:** синтаксис фильтра поддерживает только
  > `=`, `<>`, `@=` — операторов `>=`/`<` **нет** (см. `modAggregate.bas`, Core, не менять).
  > Период по датам нельзя выразить строкой-фильтром в существующем формате. Обход: фильтрация
  > по датам делается **не через `filters`**, а прямым проходом по снимку с сравнением
  > `CellRaw(r, "status_date")` в диапазон границ ПН — тем же приёмом, что и `MedianDeltaHours`
  > в 3.1, либо через `yearWeek = <ПН>` (проще и достаточно для «предыдущая неделя»: сравнение
  > по `yearWeek`, а не по датам, отдельным фильтром `"yearWeek=" & ПН`, который **можно**
  > выразить через `RowMatchesFilters`, т.к. `yearWeek` — точное значение, не диапазон).

  **Скорректированное решение:** `BuildBlock2Table(Array("in_bounds=True", "arm@=ПК;ПЛАНШЕТ", "yearWeek=" & CStr(weekAsYearWeek)))`.

**Приёмка:** колонка «Оценка» непуста только для строк, попавших в «норма»/«провал»/«мало данных»;
серая зона — видимо пустая ячейка, без подсветки; сумма «Нарядов» по всем постам не обязана
совпадать с общим числом ЗН (наряд может проходить несколько постов — фиксировать как факт,
не баг).

### 3.10 Гиперссылки / drill-down (общее требование раздела 1.1 доработок)

**Объём для этого ТЗ (минимально жизнеспособная реализация):**

1. Один встроенный JSON-дамп строк `tbDATA` за ПН и текущую неделю (`yearWeek ∈ {ПН, ПН+1}` —
   уточнить формулу «текущая» = максимальный `yearWeek` в данных, «предыдущая» = `ПН` из 2.1;
   **это разные понятия**, см. допущение 9.4). Поля дампа: `number`, `date`, `ready_for`,
   `direction`, `status_date`, `arm`, `post`, `employee`. ФИО — **включаются** (решение заказчика).
2. Дамп собирается **один раз на прогон**, встраивается в `<script type="application/json" id="rowdump">`.
3. Каждая цифра в блоках Дашборда/Блока 1/Блока 2 получает `data-numbers="ЗН1,ЗН2,..."` — список
   номеров ЗН, входящих в эту цифру (собирается в момент построения таблицы, не постфактум).
4. Клик по `<span class="drill" data-numbers="...">` — JS фильтрует массив дампа по списку
   номеров, рендерит всплывающую таблицу. Визуально `.drill` — обычный текст (без подчёркивания/
   цвета ссылки), курсор `pointer` при `hover`.

**КРИТИЧНО — конфликт экранирования (найден при ревью, см. память проекта).**
Дамп встраивается как JSON внутри HTML. Два независимых требования конфликтуют, если применить
их наивно:
- JSON-строка должна быть корректным JSON (кавычки/спецсимволы экранированы **по правилам JSON**).
- Значение при этом всё ещё лежит **внутри HTML-документа** — если исходное значение из 1С
  содержит последовательность `</script>`, она преждевременно закроет тег скрипта независимо
  от того, что говорит JSON-экранирование.

**Решение:** после `JsonEscape()` (уже есть, полная реализация с `\uXXXX`) дополнительно заменить
литерал `</` на `<\/` **внутри JSON-строк дампа** (стандартный приём для встраивания JSON в
`<script>`). `modHTMLEngine.HtmlEscape` к содержимому JSON **не применяется** — это два разных
контекста экранирования, смешивать их нельзя (`HtmlEscape` превратила бы `"` в `&quot;` и сломала
бы JSON.parse на стороне JS). `HtmlEscape` по-прежнему применяется к любому значению, вставляемому
напрямую в HTML-разметку таблиц (как сейчас).

```vba
Private Function JsonEscapeForInlineScript(s As String) As String
    JsonEscapeForInlineScript = Replace(JsonEscape(s), "</", "<\/")
End Function
```

**Приёмка:** отчёт с ФИО, содержащими `&`, `<`, `"`, открывается без ошибок консоли браузера;
`JSON.parse` дампа не падает; HTML-таблицы отображают эти символы корректно (не как `&amp;`
дважды экранированные).

### 4.1 Промпт ИИ — расширение до 7 ключей + псевдонимизация

```
Ответ строго в формате JSON: {"slide1_conclusions": "...", ..., "slide7_conclusions": "..."},
без markdown-разметки вокруг JSON."
```

**Пользовательское сообщение** дополняется блоком `block6_people` (псевдонимизированные
агрегаты по людям для слайдов 2/3/5):

```json
"block6_people": [
  {"alias": "Сотрудник 1", "pct_current": 0.62, "pct_prev": 0.55, "signatures": 12},
  {"alias": "Сотрудник 2", "pct_current": 0.40, "pct_prev": 0.48, "signatures": 8}
]
```

**Псевдонимизация — реализация и явно зафиксированный риск:**

```vba
Private Function BuildAliasMap() As Object
    ' Distinct(employee) -> "Сотрудник N", нумерация по алфавиту (StrComp, vbTextCompare),
    ' стабильно в пределах одного прогона (не персистентно между прогонами — не требуется).
    Dim names As Object: Set names = modAggregate.DistinctValues("employee", FBase())
    Dim sortedNames As Variant: sortedNames = modAggregate.SortKeys(names, numeric:=False)
    Dim map As Object: Set map = CreateObject("Scripting.Dictionary")
    Dim i As Long
    For i = LBound(sortedNames) To UBound(sortedNames)
        map(CStr(sortedNames(i))) = "Сотрудник " & (i - LBound(sortedNames) + 1)
    Next i
    Set BuildAliasMap = map ' ФИО -> алиас; обратная замена — построить перевёрнутый Dictionary
End Function
```

**⚠️ Известный риск (не устраняется в этом ТЗ, фиксируется как принятое ограничение).**
Обратная замена алиас→ФИО в тексте ИИ-вывода делается точным строковым `Replace("Сотрудник 3", ФИО)`
на уровне алиасов, а не наоборот (ФИО не ищется в тексте — модель никогда не видела ФИО, только
алиасы, значит в её ответе гарантированно встречаются только алиасы, не склонённые формы).
Поэтому проблема русских падежей ("Сотруднику 3 стоит обратить внимание" — модель может
просклонять "Сотрудник" → "Сотруднику") **действительно существует**, но масштаб ограничен:
слово "Сотрудник" в тексте перед номером может оказаться в разных падежах, а `Replace` ищет
точную строку `"Сотрудник N"`. **Обход**: заменять не строку целиком, а **только номер** —
регулярным поиском паттерна `"Сотрудник\w*\s*" & N` (без Regex-библиотек в VBA — реализовать
через `InStr`/`Mid` посимвольный поиск: найти `N` как отдельное число, отступить назад до
границы слова, заменить найденный фрагмент "Сотрудник<любой суффикс> N" на ФИО целиком).
Это дополнительная строковая функция `ReplaceAliasFlexible(text, N, fio)`; если её не успеть
реализовать корректно в срок — принять как известное ограничение и падёж не чинить (текст
останется читаемым в 95% случаев, "Сотрудник 3" почти всегда используется в именительном падеже
в деловых текстах LLM).

   при коллизии (одна и та же неделя в нескольких годах) берётся более поздний год. Если
   заказчик имел в виду что-то другое (например точный `yearWeek` вида `202643`) — требует
   уточнения до реализации раздела 2.1.
4. **«Текущая» и «предыдущая» недели в drill-down (раздел 3.10) — не одно и то же**, что
   ПН/год в Дашборде. Зафиксировано как `{ПН, ПН следующая присутствующая в данных}` —
   то есть буквально «предыдущая и текущая» в бытовом смысле, не «ПН» из `REPORT/WEEK`.
   Если это разночтение критично — уточнить до реализации.
5. **`REPORT/MIN_RECORDS` за одну неделю (раздел 3.5)** — порог 5, применённый к данным
   одной недели вместо всей истории, статистически более строгий (меньше сотрудников
   пройдёт порог). Не корректирую значение по умолчанию самостоятельно — решение заказчика,
   зафиксированное в `Презентация и блоки данных.md` §6 п.9, оставляет `MIN_RECORDS` как есть.
6. **Псевдонимизация с русскими падежами не решается полностью** (раздел 4.1) — принимается
   риск, а не блокирующая доработка, если не будет прямого указания заказчика на важность.
7. **График Блока 2 (3.11)** — переключателя «% планшета / Нарядов» нет, зафиксирован один
   режим (% планшета). Если нужен переключатель — отдельная (небольшая) доработка.
