# Сквозное тестирование ReportMTO v7.0 — сценарий и правила

> Версия документа: v1.0 от 07.09.2026.
> Исполнители: [`tools/run-e2e-tests-v1.ps1`](../tools/run-e2e-tests-v1.ps1) +
> [`tests/modSelfTest.bas`](../tests/modSelfTest.bas). Эталон ожиданий —
> [`tests/expected.md`](../tests/expected.md).

## Что это

Один прогон скрипта собирает и проверяет всю цепочку «книга → загрузка JSON →
блоки отчёта → upsert → офлайн-отчёт». Запускается на копии книги (оригинал
`build\ReportMTO v7.0.xlsm` не меняется). Выход: консоль + лог
`%TEMP%\e2e_result.txt`; код возврата 0 = все шаги PASS, 1 = есть FAIL.

## Запуск

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "tools\run-e2e-tests-v1.ps1"
```

Параметры (по умолчанию не нужны):

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `-BookPath` | `build\ReportMTO v7.0.xlsm` | книга для прогона (копируется в `%TEMP%`) |
| `-ResultFolder` | `C:\Projects\ReportMTO\result` | папка, куда `DebugGenerateOffline` пишет отчёт |

Требование к машине: Excel 2016+, включён «Доверять доступ к объектной модели
проектов VBA» (как для сборки), все процессы EXCEL.EXE закрыты перед стартом.
Во время прогона на экране будет виден Excel; диалог «Отладочный отчёт сохранён»
закрывается автоматически (SendKeys) — нажимать ничего не нужно, окна не трогать.

## Шаги прогона (и что означает каждый провал)

| Шаг | Действие | Ожидание | Провал означает |
|---|---|---|---|
| PREP_BOOK | книга найдена | — | неверный `-BookPath` |
| STEP1_ROWS | загрузка `test_sppr_tablet_v1.json` в пустую `tbDATA` | 25 строк | потеря строк на разворачивании JSON |
| STEP1_SELFTEST | `modSelfTest.SelfTest`: 40+ CHECK (структура 7 слайдов, промпт, маркеры, STUB, числовые контрольные значения) | все `=1`, есть `DONE` | строка с `=0` или `CHECK:VBA_ERROR` выводится в консоль — искать по тексту CHECK |
| STEP2_RELOAD | повторная загрузка того же файла | 25 строк | сломан `Key` / отбор несовпавших строк |
| STEP3_ROWS | загрузка `test_upsert_same_keys_v1.json` | 25 строк | 2 строки = `qExistingData` не нашёл таблицу; 26 = пустая строка в таблице |
| STEP3_UPSERT | `modSelfTest.SelfTestUpsert`: `ЗН-002` встречается 2 раза, обе строки `arm = ПК` | `UPSERT_ARM_PK=1`, `DONE_UPSERT` | upsert работает как anti-join (старые строки не замещаются) |
| STEP4_OFFLINE | `modMain.DebugGenerateOffline` + проверка свежего `debug_*.html` | нет `{{` (плейсхолдеры заменены), есть `[offline]` и `drill-dump` | разобрать по трём флагам в выводе |

Лог SelfTest — `%TEMP%\selftest_result.txt`; готовый HTML-отчёт для глаз —
`%TEMP%\selftest_out.html`; лог офлайн-прогона — свежий `result\debug_*.html`.

## Числовые контрольные значения внутри SelfTest

В [`tests/modSelfTest.bas`](../tests/modSelfTest.bas) (v1.1) добавлены CHECK по
разделу «Контроль отчёта v7.0» в [`tests/expected.md`](../tests/expected.md):

- `CHECK:BLOCK1_DGM_000` — Блок 1, ДГМ «Итого» = **0,0%** (окно {101, 202535}:
  2 события ПК, планшетов 0);
- `CHECK:BLOCK1_DENT_EMPTY` — Блок 1, ДЭНТ = «Нет данных» (события ДЭНТ только
  на неделе 35/2026, вне окна `REPORT/WEEK`);
- `CHECK:DASH_YTD_476` — Дашборд «С начала года»: **47,6%** (10 планшетов из
  21 события 2026 года, ДГМ + ДЭНТ);
- `CHECK:BLOCK6_DGM_IVANOV` — Блок 6, ДГМ: строка «Иванов И.И.» с 1 подписанием
  за ПН (ячейка «>1<»).

Эти значения верны только для `test_sppr_tablet_v1.json` и набора ключей
`Variable` по умолчанию (авто-неделя, `REPORT/MIN_RECORDS` и т.п.). После STEP3
контрольные цифры Блока 1 смещаются (строки `ЗН-002` стали ПК — см.
`tests/expected.md`), поэтому числовые CHECK выполняются только на шаге STEP1.

## Правило добавления нового теста

1. Положить новый JSON в `tests\` (UTF-8 без BOM) и описать его в
   [`tests/expected.md`](../tests/expected.md): сколько строк ждать, какие
   граничные случаи покрывает, контрольные цифры блоков.
2. Если нужны проверки в VBA — добавить процедуру или CHECK в
   [`tests/modSelfTest.bas`](../tests/modSelfTest.bas) (имя CHECK уникально,
   ожидание — строго `=1`), поднять версию в шапке модуля с датой и описанием.
3. Добавить шаг в [`tools/run-e2e-tests-v1.ps1`](../tools/run-e2e-tests-v1.ps1)
   (загрузка файла → проверка строк → вызов процедуры → `StepResult`), поднять
   версию в шапке скрипта с датой и описанием.
4. Обновить этот документ (таблица шагов) и прогнать скрипт до зелёного.
5. Исходники `.ps1` держать ASCII-only (PowerShell 5.1 читает без BOM как ANSI),
   сравнения с кириллицей — только в VBA. `.bas` — в UTF-8 в репозитории,
   перекодировку в ANSI 1251 делает скрипт.

## Что тест НЕ проверяет

- Синтаксис M и типы аргументов Power Query — только Excel при обновлении
  запросов (сам прогон их обновляет, но семантику M не ревьюит).
- Formula Firewall — уровень конфиденциальности настраивается вручную один раз.
- `deltaHours` при инкрементальных выгрузках (метрики считаются до слияния —
  ограничение архитектуры, см. `tests/expected.md`).
- Формат `Key` (ISO-дата внутри строки) — проверяется глазами, тестом не ловится.
- Числовые контрольные значения после upsert-прогона (данные намеренно меняются
  на шаге STEP3).
