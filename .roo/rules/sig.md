Для модулей, у которых есть папка сигнатуры (./src/sig/):

Если статус в сигнатуре CLEAN — для решений "нужно ли трогать этот модуль" и для общих вопросов о нём ("что делает функция X", "какие есть процедуры") читать только сигнатуру, не открывать исходный код.
Если статус DIRTY — сигнатуре не доверять. Любой вопрос об этом модуле требует чтения полного кода, даже если вопрос не связан с правкой.
Если модуль нужно редактировать — читать полный исходный код всегда, независимо от статуса сигнатуры. Сигнатура никогда не заменяет код при правке.
Сразу после внесения правки в модуль — поставить статус DIRTY в его файле сигнатуры. Пересборку сигнатуры (переход обратно в CLEAN) агент не делает сам в рамках обычной работы — она запускается командой /c сигн (отдельно) или происходит автоматически внутри /c push / /c синхрон перед коммитом.
Не заводить сигнатуру для модуля, который активно переписывается в рамках текущей задачи — сначала стабилизировать код.
Что не делать
Не читать полный код модуля "на всякий случай", если сигнатура CLEAN и вопрос не требует правки.
Не пропускать пометку DIRTY после правки.
Не пересобирать сигнатуру самостоятельно, по своей инициативе — только через команду /c (сценарий сигн, push или синхрон).
